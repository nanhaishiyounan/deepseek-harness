# @deepseek-ai/dsh-client-ui-mobile

English | [中文](README.zh.md)

The mobile v3 client shell: a cold-chain ledger take on the NocoBase business system's AI-colleague entry — two tabs (消息/我的), a session list with flat stamp avatars and kind badges, a ticket-bubble chat flow (6px speaking corners, markdown-rich narratives), and the fill-and-stamp loop the PC side deliberately does not have (three-tier draft card with phase stamp → 确认写入/驳回 → agent `nb_create` → metric receipt card → re-edit diff). Built on antd-mobile v5 widgets with fully hand-drawn brand surfaces, over the same `/api` gateway the PC shell uses; sessions, the knowledge graph, and business rows are shared verbatim.

- **Composition**: `apps/web`'s `mobile.html` entry boots [`AppMobileEntry`](src/client/entry.tsx). The page reads no boot manifest: a ~65-line unary RPC client ([rpc.ts](src/client/rpc.ts)) speaks the same `/api/<method>` wire as the PC fetch carrier. antd-mobile's global base loads at the entry; the `--adm-*` theme maps onto `--dshm-*` on `.dshm-root` ([tokens.css](src/client/tokens.css)): the ink-teal/mist/frost brand axis, pass/hold/reject semantics, the three temperature-layer accents, light and dark swapped as whole tracks (dark selected foreground switches via `--dshm-on-primary`), tabular digits everywhere and the monospace ticket face on row numbers.
- **Two-tab IA (v3)**: chats (default) and me; the v1 tab hashes and the retired contacts route redirect onto the tabs so old deep links — including the PC preview iframe — keep working. New chats ride the `+` bottom sheet ([NewChatSheet.tsx](src/client/messages/NewChatSheet.tsx): fill assistant first with form chips, three recent sessions) opened from the chats header and the chat header alike; the sheet only creates sessions, never sends as the user.
- **AI colleagues (v3)**: the roster comes from `agentPreset.list` (including each preset.yml `welcome` block) enriched by the local visual table ([colleagues.ts](src/client/colleagues.ts): stamp color/acronym/duty/welcome metadata — the v2 gradient avatar system is retired); the fill assistant is the single table-holding colleague whose welcome capabilities and starter chips project from the six-form registry ([formRegistry.ts](src/client/formRegistry.ts)). The contacts 发消息 entry only creates the session — nothing is ever sent as the user; an empty session renders the local welcome card.
- **Chat**: `session.history` is folded ([fold.ts](src/client/fold.ts)) into bubbles (AI left / user right, 18px radius with the 6px speaking corner and the stroked AI seal on the avatar), day separators, tool rows with running/done/error state, and the collapsed KG evidence entry row (opens the bottom sheet); narratives render through the markdown-it + DOMPurify pipeline ([rich.ts](src/client/messages/rich.ts): strong key-info underline, square-bullet lists, two-column ticket tables, numeric conclusion lines promoted to half-width metric cards); the three motions (item entrance / pick feedback / the stamp landing) all respect prefers-reduced-motion; freshness comes from polling (1.2s running / 5s idle) with a cancel button over `session.cancel`.
- **Seven-kind message protocol (v3)**: structured payloads all ride the ```dsh``` fence ([protocol.ts](src/client/protocol.ts): ask_choice/ask_field/form_draft/form_confirm/reject_flow/submit_receipt under the `v:3` envelope; broken fences degrade to plain text without breaking the flow); welcome deliberately never touches the wire. The fold ([fold.ts](src/client/fold.ts)) splits each assistant message into narrative plus structured items — fences never render inside a bubble; a pick is just an ordinary user text, with the answered state (greyed group / highlighted pick / capsule reply) derived on replay; 确认/驳回 are fenced user actions (ActionBadge), replacing the old `确认推送：` protocol text.
- **Fill + human review + submit**: the v3 draft ([forms/v3/DraftCard.tsx](src/client/forms/v3/DraftCard.tsx)) renders the three tiers (需要你定 / 请确认·AI 推导 with rationale / 系统生成 folded) with the phase stamp, 确认写入/驳回 right on the card, and re-edits riding revision+1; the receipt is a metric card ([forms/v3/ReceiptCard.tsx](src/client/forms/v3/ReceiptCard.tsx): money hero / two-column summary / three-step trail / row-number stamp). Card phases replay from the log by draftId+revision ([cardState.ts](src/client/cardState.ts)) with superseded revisions hidden; v2 legacy sessions keep the old fence/prefix/text-receipt replay and the two-step review card ([form-draft.ts](src/client/form-draft.ts), [task-cards.tsx](src/client/forms/task-cards.tsx)). Unsubmitted edits persist in localStorage keyed by the draft content hash ([draftStore.ts](src/client/draftStore.ts)).

The route: served at `/mobile` by the web-app bundle's `mobileEnabled` config (raw `dist/mobile.html`); the PC-side phone-bezel preview lives in `@deepseek-ai/dsh-client-ui-mobile-preview`.

## Model Experience

None, as a browser-side page the mobile shell renders gateway data and registers nothing model-facing; the agent behind a session sees the same inputs the PC workbench renders (the preview view's view-context projection is title-level by design). The mobile flow changes only the shape of user messages — short slot-filling answers and explicit 确认推送/驳回 go-aheads in the durable log — never the model-visible surface this package owns.

#### KV Cache effect

None; this package neither assembles nor sends a provider request.

## Known Limitations and Deferred Work

- Demo-grade auth only: any six-digit code logs in (`verifyCode` is the seam for a real channel); deployments stay protected by the host's disk-level access control.
- Chat freshness is history polling (1.2s while a turn runs, 5s idle), not the mux/host streams; the in-progress text is not token-streamed on mobile this batch.
- The unread dot and the 待审核 chats filter are locally derived (read watermark / pending marks in localStorage); the wire carries neither unread counts nor a session-scoped review state — a reload keeps the log-replayed card phases but resets the local marks.
- The field-widget mapping covers input/number/date/bool/enum/relation with a locally measured enum vocabulary; the wire's `nocobase.listMeta` does not project select options, and interface long-tails fall back to plain text.
- The relation picker labels options by the target's `name`/`nickname` column and submits the target row id; drafts therefore carry relation ids (the colleagues' personas resolve names to ids before drafting).
