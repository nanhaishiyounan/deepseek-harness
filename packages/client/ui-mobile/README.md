# @deepseek-ai/dsh-client-ui-mobile

English | [中文](README.zh.md)

The mobile v7 "AI colleague" client shell: a food-company mobile workspace — a four-tab (消息/同事/工作台/我的) twelve-route surface, the AI-colleague chat flow (ticket bubbles + markdown-rich narratives + the v3 fill loop + the v5 report card), and the work loop (report card → create task → isolated execution → source-chat confirmation). The visual language is the W9「Sauce Amber 酱园琥珀」system (the warm-paper canvas `#fbf5eb`, persimmon `#b4530a` heartbeats on the CTA/key figures/selected states, roast-ink text, and the seal grammar — paper-label bubbles with the fold notch, capsule chips with the vermilion dot, round stamps for the hero batch seal and the send button, ledger-paper receipt cards with the 收讫 sign-off chop; links and the form-assistant seal ride the persimmon deep/lifted grades (W10 retired the W7 Prussian-blue anchor and the dark track's blue-gray link); the token single source is [demos/acceptance-w9/design-language-w9.md](../../../demos/acceptance-w9/design-language-w9.md)) plus the W8 accessibility increments (the `--dshm-focus-ring` keyboard halo, the `--dshm-link` text grade, the 40px secondary / 44px primary touch ladder, the 16px input floor, and dark-track input wells stepped off the card). Element-level controls ride antd-mobile v5 widgets (buttons, tags, badges, progress, skeletons, inputs — faces dialed through the components' CSS variables on the `--dshm-*` track) with hand-drawn layout containers, over the same `/api` gateway the PC shell uses; sessions, the knowledge graph, and business rows are shared verbatim.

- **Composition**: `apps/web`'s `mobile.html` entry boots [`AppMobileEntry`](src/client/entry.tsx). The page reads no boot manifest: a ~65-line unary RPC client ([rpc.ts](src/client/rpc.ts)) speaks the same `/api/<method>` wire as the PC fetch carrier. antd-mobile's global base loads at the entry; the `--adm-*` theme maps onto `--dshm-*` declared on both `.dshm-root` and an `html[data-theme]` twin ([tokens.css](src/client/tokens.css)) — the dark track re-declares the whole `--adm-*` map on its own dials (W10; the light-only mapping had left dark portals on antd defaults like the capsule tab's #f5f5f5), and every native `button` under the shell takes the UA reset from a low-priority cascade layer (`@layer dshm-button-reset`), so module classes and antd faces own their look without a specificity fight with the bare selector. antd-mobile portals (Popup/Picker/DatePicker/Dialog/Modal) mount into a shell-owned portal host ([portal.ts](src/client/portal.ts)), so they inherit the tokens and stay inside the 430px shell. The root draws the 430px phone shell: fluid full-width on narrow viewports, a centered 24px-radius bezel with an outer shadow at ≥720px desktop (where the root's translateZ contains the fixed portal layers), and the body's desk color mirrors the theme (App.tsx).
- **Visual language (W9 Sauce Amber)**: the token system takes [design-language-w9.md](../../../demos/acceptance-w9/design-language-w9.md) §3 as its single source, both tracks declared whole in [tokens.css](src/client/tokens.css) — the base-name layer (`canvas/card/card2/brand/brand-deep/brand-soft/on-brand/anchor/ink/ink-sub/line/line-strong` + the five semantic states + the seal slots), the six-grade type ramp plus the mono numeric track (`fs-display 30/800 … fs-num-lg 32 mono tabular`), and the space/radius/shadow/motion ladders (`space-1..6`, `r-card 20`, the `shadow-seal` persimmon dye, the `motion-stamp` stamping curve); component forms ride the seal-grammar global hook classes (`.dshm-seal-chip` capsule, `.dshm-seal-cta` the one solid persimmon capsule per screen, `.dshm-bubble-paper-user/ai` paper-label bubbles, `.dshm-stamp-solid/faint` the stamp grades); W9-B6 migrated the core semantic names (primary/foreground/muted/border/fs-*) to the base names, while a transitional alias tail survives (on-soft ×22, stroke-soft ×15, work-*/stamp-* etc. — 73 css `var()` reads) for the next batch to migrate, with the alias declarations kept in tokens.css as the compatibility layer.
- **IA (v6 four-tab, twelve routes)**: `#/` (home, the default landing), `#/chats`, `#/chat/:id`, `#/work`, `#/work/:id`, `#/todos`, `#/alerts`, `#/docs`, `#/me`, `#/tasks`, `#/files`, `#/agents`, `#/login`; the tab bar's four items are 消息/同事/工作台/我的 (home/agents/work/me, a 58px bar with 22px line icons), `#/chats` is the all-chats full-screen layer with the PageNav back header, chat and work detail render as full-screen layers, todos/alerts/docs/tasks/files as secondary pages ([router.ts](src/client/router.ts) / [MobileShell.tsx](src/client/shell/MobileShell.tsx)). The v1/v2 hashes fold: workbench→work, contacts→agents, messages/data/kg→the all-chats layer, profile→me — old deep links (the PC preview iframe included) land on a live page. The four tab pages stay mounted (keep-alive, W8 B1): a lazy first visit mounts the page, `[hidden]` toggles the visible one so scroll positions, filters, and half-typed state survive a tab switch, and each hidden page suspends its data reads until it becomes visible again; every layer route still remounts behind the 14px push transition (fade between tabs, both at the mock's pageIn .22s ease, respecting prefers-reduced-motion), and route changes land focus on the page body without scrolling.
- **Home (v6 消息 form)**: the gradient hero greeting, the search-box entry (landing on the all-chats layer, which owns the real filtering), the compact today-ledger chip strip, the quick-task chips, the colleagues' avatar rail (right-edge fade), and the recent-chats conv-item rows — presence dot, one-line projection preview, relative time, and the unread dot off the draftStore watermark ([HomeView.tsx](src/client/home/HomeView.tsx)).
- **AI colleagues (v6 roster form)**: the roster comes from `agentPreset.list` (including each preset.yml `welcome` block) enriched by the local visual table ([colleagues.ts](src/client/colleagues.ts): stamp color/acronym/duty/welcome plus the v6 group/skills/status fields); the agents tab renders the capability bands (内容与创意/数据与技术/职能与效率, ungrouped presets under 更多 AI 同事, empty bands drop their headings) with skill pills and the presence chip — the AI presence stays 在线 by product semantics. The work tab's 2-column tool grid derives one card per preset whose 去聊聊 rides the real `createSession` + `promptSession` lane with the colleague's first starter as the opener ([WorkView.tsx](src/client/work/WorkView.tsx)); the home rail and the roster rows ride `createSession` — nothing is ever sent as the user; an empty session renders the local welcome card. The fill assistant stays the single table-holding colleague whose welcome capabilities and starter chips project from the six-form registry ([formRegistry.ts](src/client/formRegistry.ts)).
- **Chat (v6 form)**: `session.history` is folded ([fold.ts](src/client/fold.ts)) into the two-state bubbles (bot: the white bordered plate with the 6px top-left corner; user: the gradient with the top-right corner, both 78% wide with the .28s entrance), the breathing three-dot typing plate, day separators, tool rows with running/done/error state, and the collapsed KG evidence entry row; narratives render through the markdown-it + DOMPurify pipeline ([rich.ts](src/client/messages/rich.ts)) with fenced code lifted out whole before the display-term pass and rendered as the deep code plate with its language label and copy entry (clipboard → execCommand fallback → toast). The input bar carries the + entry over the slide-up quick panel — the colleague's own starters as commands plus the real tool lanes (W11-B2: voice/camera/album/file as a 2×2 capsule-tile grid; the voice tile renders only where the Web Speech engine exists under a secure context, so the WeChat webview and plain HTTP show three tiles, and a mid-session engine failure degrades to a toast, never a stuck listening card), the draft-attachment strip above it (one chip per picked image/document through uploading → ready → failed with a human hint and a remove ×; a ready image rides `data.describeImage` for a server-side VLM description and a pdf/md/txt rides `data.extractText`, the returned text landing as a visible, deletable quote block spliced ahead of the typed draft so `send(text)` stays plain text), the 46px capsule textarea whose box arithmetic lives on the wrapper (W11-B1), and the round persimmon send stamp; consecutive tool rows fold the flow gap into one status group (X20). Prefab tags (welcome starters, quick commands, context chips, field-ask suggestions) assist input (W9-B1): a pick replaces the whole draft, focuses the box with the caret at the end, and nothing goes out until the user edits or taps send; fenced actions (choice bubbles, approval/plan/report cards) still fire at once. The home "recent chats" filters work sessions out (the isolation set is a local registry). Freshness comes from polling (1.2s running / 5s idle) with a cancel button over `session.cancel`.
- **Message protocol (v3 + the v5 report fence + the W1 approval fences)**: structured payloads all ride the ```dsh``` fence ([protocol.ts](src/client/protocol.ts): ask_choice/ask_field/form_draft/form_confirm/reject_flow/submit_receipt/report/approval_pending/approval_result under the `v:3` envelope; broken fences degrade to a collapsed original-text notice without breaking the flow); welcome deliberately never touches the wire. The report card ([ReportCard.tsx](src/client/messages/ReportCard.tsx)) renders the metric grid / entry rows / table / action buttons; the count bounds are part of the contract (metrics 1–6, rows ≤8, table ≤5 columns ×10 rows, actions ≤4) and an out-of-bounds card degrades whole. Four action kinds: view (an in-product route), create-task (opens the task form), send (posts a full instruction as the user), link (external).
- **Approval card (W1)**: an open approval todo renders as the actionable card ([ApprovalCard.tsx](src/client/messages/ApprovalCard.tsx)) — document summary (type, number, amount, attempt round), the state stamp, an optional remark input, and the 同意/驳回 pair that sends the fenced `approval_confirm` user message the assistant answers with `nb_approve`; the post-act `approval_result` card reads back the landed state (the state word may arrive in either spelling — the parser normalizes the closed Chinese vocabulary onto the wire's English enum), the actor, the remark, and the date, read-only with the state chip (pending amber / level-2 purple / approved green / rejected red).
- **Work loop (v5 semantics on the v6 axis form)**: [workStore.ts](src/client/workStore.ts) (localStorage `dsh-mobile-work`) holds four-state work items (待处理→进行中→待确认→已完成, a transition-guarded state machine); the report card's 创建处理任务 opens the form modal ([actions.ts](src/client/actions.ts)) and posts the M1 notice to the source chat; execution runs in an isolated exec session — live mode creates a real session and posts the M2 directive, completion posts M3 back to the source chat, rework posts M4; the work detail page ([work/workTimeline.ts](src/client/work/workTimeline.ts)) carries the two-mode timeline: live folds the exec session's log into steps and a result, demo advances a scripted sequence, and a doing item offers the 重新执行/手动完成 escape hatch (manual completion rides the same M3 lane). The v6 axis renders the 56px right-aligned time column (the live tool row's clock / the demo's 01-style ordinal), the halo dot over the 2px spine, and a derived done/total progress bar on the gradient fill. The files page (`#/files`) renders three complementary sections — 最近文件 = every artifact from the last 7 days (rows badged with their AI origin), AI 生成 = its AI-origin filtered subset, 收藏 = the local stars (with report previews); the tasks page (`#/tasks`) splits mine/team.
- **Two modes (live/demo)**: [runMode.ts](src/client/runMode.ts) decides from the profile's explicit AI-preference switch plus an `llm.models` probe (no model catalog → demo mode: no exec session is created, the timeline simulates — the demo never impersonates the real lane); the first-run demo seed ([demoSeed.ts](src/client/demoSeed.ts): team tasks and a pinned report, all demo-marked) and 清除演示数据 removes exactly the demo items.
- **Fill + human review + submit**: the v3 draft ([forms/v3/DraftCard.tsx](src/client/forms/v3/DraftCard.tsx)) renders the three tiers (需要你定 / 请确认·AI 推导 with rationale / 系统生成 folded) with the phase stamp, 确认写入/驳回 right on the card, and re-edits riding revision+1; the receipt is a metric card ([forms/v3/ReceiptCard.tsx](src/client/forms/v3/ReceiptCard.tsx)). Card phases replay from the log by draftId+revision ([cardState.ts](src/client/cardState.ts)) with superseded revisions hidden; v2 legacy sessions keep the old fence/prefix/text-receipt replay. Unsubmitted edits persist in localStorage keyed by the draft content hash ([draftStore.ts](src/client/draftStore.ts)).

The route: served at `/mobile` by the web-app bundle's `mobileEnabled` config (raw `dist/mobile.html`); the PC-side phone-bezel preview lives in `@deepseek-ai/dsh-client-ui-mobile-preview`.

## Model Experience

None, as a browser-side page the mobile shell renders gateway data and registers nothing model-facing; the agent behind a session sees the same inputs the PC workbench renders. The mobile flow changes only the shape of user messages — short slot-filling answers, the fenced 确认写入/驳回 actions, and the v5 work-loop action messages (the M1 creation notice, M2 execution directive, M3 completion notice, M4 rework directive, and the report card's send action) all ride the durable log as real user messages — model-visible ⟺ log-reconstructable; welcome never touches the wire, and the work store itself stays off the wire.

#### KV Cache effect

None; this package neither assembles nor sends a provider request.

## Known Limitations and Deferred Work

- Login rides the real `nocobase.signIn` channel (account + password against NocoBase's basic authenticator; wrong credentials surface the server's refusal). A token that expires mid-session clears the token, toasts once, and lands on the login gate; work items, drafts, and both outboxes survive, and re-login re-backfills and re-dispatches (W8-B3).
- Deferred by product form (W8 verdicts, [blueprint](../../../research/2026-10-04-w8-mobile/blueprint.md)): the px type ramp does not follow the system Dynamic Type (a 430px-shell decision — keyboard readability rides the focus ring instead); no skip-to-content link (the bottom-tab form keeps keyboard paths short); landscape layout is not tuned (the portrait phone shell is the product shape).
- Chat freshness is cursor polling (800ms while a turn runs, 5s idle; W8-B3): the first read pages the tail window, later polls send only the `afterSeq` cursor and append, and the feed re-bases on visibility or a large page — still not the mux/host streams, and the in-progress text is not token-streamed.
- Work data roams with the account (W8-B3): [workSync.ts](src/client/workSync.ts) mirrors every write into the server-side `wfl_mobile_work` projection (the gateway enforces per-account row scope) and backfills on login; a failed sync parks in a durable outbox that re-dispatches on re-login. Signed-out or offline the store stays the pure-local demo it was; the fold/replay semantics are untouched.
- Work-session isolation is a local registry: the isolation set stays on the device, so other devices and the PC still list the exec sessions.
- The unread dot and the 待审核 chats filter are locally derived (read watermark / pending marks in localStorage); the wire carries neither unread counts nor a session-scoped review state — a reload keeps the log-replayed card phases but resets the local marks.
- The field-widget mapping covers input/number/date/bool/enum/relation with a locally measured enum vocabulary; the wire's `nocobase.listMeta` does not project select options, and interface long-tails fall back to plain text.
- The relation picker labels options by the target's `name`/`nickname` column and submits the target row id; drafts therefore carry relation ids (the colleagues' personas resolve names to ids before drafting).
