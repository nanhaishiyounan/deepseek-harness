# @deepseek-ai/dsh-governance-engine

[English](README.md) | 中文

治理引擎 provider：在 SQLite 存储之上实现 `ctx.governance`（血缘边、质量规则、告警事件），带活的五源资产采集器、湖仓背书的质量评估器、可选的告警 webhook 通道（Config 开关，默认关）。采集器按源降级 —— Neo4j 回退 kg-graph SQLite 注册表、WeKnora API 回退 kb-sqlite 文档表 —— 无外部凭据的部署仍能盘点全部五源（B6：252 资产）。质量评估在 `evaluate()` 内惰性解析湖仓引擎：插件加载序打不破它，无引擎的部署其余各面继续工作。

## 模型体验

间接：经面板渲染的网关 governance 域；引擎自身不注册任何 prompt、schema 或工具。

#### KV Cache 影响

无：引擎读与评估从不自行进入请求；记录仅在会话显式请求网关响应时出现。

## 已知限制与遗留工作

- 质量评估需要湖仓引擎；缺引擎时 `evaluate()` 报结构化拒绝，目录、血缘、规则、告警继续工作。
- 规则评估按需触发（`evaluate()` 与面板的运行按钮）；尚无定时评估，告警事件只在有东西评估或记录时出现。
- webhook 通道只投递告警事件；规则变更与目录通知随更丰富的通知面到来。
- 血缘边是记录出来的、不是推导出来的：摄取管线与同步运行显式追加，管线之外手工跑的任务不留边。
