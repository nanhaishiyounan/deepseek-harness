# Agent Note: Mobile v2 — the WeChat-style AI-colleague entry and the fill-submit loop

Status: implemented

English | [中文](2026-09-20-mobile-v2-ai-colleagues.zh.md)

## Problem

The v1 `/mobile` (M3) shipped a "DSH phone shell": four tabs mirroring the PC workbench, with AI form filling that only assists — it never submits. The user rejected that direction: what they want on the phone is a **NocoBase business-system AI-employee entrance** — a WeChat-style chat where every peer is an AI colleague, plus the fill-and-submit loop the PC deliberately does not have (draft card a human can edit → review card a human judges → write to the business table → receipt), and a UI that carries real design intent (an open-source component library is explicitly authorized).

## Decision

Rebuild the UI tree only; keep the v1 plumbing verbatim (rpc.ts, sessionsService.ts, fold.ts, the mobile.html hosting chain, the preview iframe, the preset contract). Eight decisions from the reviewed plan ([plans/2026-09-20-mobile-v2-ai-colleagues/PLAN.md](../../../../plans/2026-09-20-mobile-v2-ai-colleagues/PLAN.md)) execute as follows.

**Two-tab IA (消息/我的).** The v1 workbench/data tabs are deleted; their Q&A duty folds into a read-only 经营参谋 colleague. The v1 hash heads (messages/workbench/data/profile/kg) redirect onto the new tabs in the router, so old deep links — including the PC preview iframe — keep landing. `#/login` under a stored identity falls through to chats (a first-run bug the v2 acceptance caught: the shell rendered an empty body).

**The fill-submit loop rides the session, not the wire.** Confirm and reject are ordinary user messages (`确认推送：…final fields JSON…` / `驳回：…`); the write goes through the agent's `nb_create` confirmation contract and the durable log stays the single audit of what the human confirmed. `nocobase.create` remains absent from the wire by design. Card phases are **derived by replay** (cardState.ts): a confirm-push claims the earliest not-yet-submitted card of its collection, the receipt settles the newest pending card of its collection, a reject discards the latest draft card — so a reload and the PC preview see identical card states. The gap between 提交审核 (a local pending lock) and the confirm message landing in the log is a local overlay plus localStorage edits keyed by a content hash of the AI draft (a changed draft invalidates stale edits).

**antd-mobile v5 widgets, hand-drawn chat surfaces.** Library: TabBar/SafeArea/Input/TextArea/Picker/DatePicker/Switch/Stepper/Button/Dialog/Steps. The Picker/DatePicker/Relation fields open their popup layers through the functional-children `actions.open` binding on the rendered span (antd-mobile v5's contract for selector popups). Hand-drawn (CSS Modules): the six-element session rows, bubbles (AI left / user right, 16px radius with the 4px speaking corner), the message flow, the composer, and the four card shells (draft / review / rejected / receipt). Theming rides `.dshm-root` (`--adm-*` and `--dshm-*` variable tracks; dark mode is a `data-theme='dark'` second track toggled on the me tab). v1's tokens.css never attached `.dshm-root` to the DOM — its variables were dead — v2 has the App root carry the class. Two library facts surfaced: antd-mobile v5 has no Search component (self-drawn) and its TabBar renders divs, not `role=tab` (e2e asserts by text).

**Field widgets map the schema.** `nocobase.listMeta`'s field.type (measured: string/integer/float/bigInt/dateOnly/boolean/belongsTo/text) maps to Input/Stepper/DatePicker/Switch/Picker; select vocabularies (status columns) ride a locally measured table because the wire does not project options; `belongsTo users` stays read-only text, business relations become target-table pickers.

**Three contract fixes the real-model acceptance found** (v1 never reached these paths):

1. `nb_create` relation fields need the target row's **numeric id**, not its name — a name drew HTTP 500. The colleagues' personas now resolve names to ids before drafting; the relation picker's value is the id with the name as label, and the review diff renders the id back as the row label.
2. The model interleaves `//` comments into the fenced JSON draft ("supplier=6 对应宏发食品"), which breaks `JSON.parse` for the whole block. The parser now strips `//` lines (model-output tolerance), and the personas forbid comments inside the block.
3. See `#/login` above.

**Dependencies (the maintained-dependencies policy).** antd-mobile@5.43 (MIT) and lucide-react@1.47 (ISC) enter `dsh-client-ui-mobile` as runtime `dependencies` — the ui-primitives pattern (shiki/katex): the staticLinked bundle keeps bare specifiers external, and apps/web's Vite bundles them on demand. Measured: mobile chunk 220.6 kB (gzip 76.8 kB) + css 47.7 kB (gzip 9.1 kB); the package's lib/index.js grew 63.7 → 89.8 kB. The selection report chose antd-mobile over tdesign-mobile-react (runner-up) and rejected `@ant-design/x` (peers the full antd, +445 KB gzip).

**Three new colleagues** (examples/kb-agent/agent-presets/): `purchase-assistant` (hub_po domain), `quality-assistant` (srm_audit_checklists/srm_capas), `business-advisor` (read-only: kb + lakehouse + nocobase reads with `writes: false`). Personas follow the mobile-form-assistant six-step contract (fenced draft → wait → confirm-push → nb_create → receipt `业务表 X 行 id=N 已创建`); the roster discovers them automatically (`agentPreset.list` smoke-checked, none broken). A local visual table (colleagues.ts) carries each colleague's gradient, acronym, duty, editable forms, and opening shortcut.

## Consequences

- The mobile surface now owns a submit loop the PC does not: the same session log carries slot-filling answers, the human's confirmed final fields, and the agent's receipt — one audit trail per submitted row, replayable on both surfaces. The rejected branch is provably write-free (acceptance asserted zero new rows).
- v1's WorkbenchView/DataView/TaskCardView are gone; the KG evidence cards stay in the chat flow, with the dead jump into the deleted data tab removed.
- The unread dot and the 待审核 chats filter are locally derived (read watermarks / pending marks in localStorage) because the wire carries neither unread counts nor review state — a reload keeps the log-replayed card phases but resets the local marks; the README states this.
- The enum vocabulary table and the relation-id convention are now persona-facing contract: future colleagues that draft business rows must resolve relation names to ids and keep enums to the measured vocabulary, or their drafts render as plain text fields.

## Alternatives considered

- **Keep the four-tab shell and add a submit button.** Rejected: the four tabs were exactly the rejected PC-mirror stance; the two-tab chat IA is the product.
- **A `nocobase.create` wire method for the submit.** Rejected (plan D4): reads-first is intentional; the agent's `nb_create` confirmation flow already audits the human's exact confirmed fields in the durable log, and a wire write would bypass that audit.
- **WebSocket push (events.mux) instead of polling.** Deferred (plan D5): the mux stream has no `since` continuation, and coupling the UI rewrite to a channel swap doubles the risk; polling was already proven in M3.
- **tdesign-mobile-react as the widget library.** Runner-up in the selection report (React-agnostic core, CSS-variable theming); antd-mobile won on component coverage (18/18), weekly downloads, and the pure `--adm-*` variable surface.
- **Storing card phases in a server-side table.** Rejected (plan D6): replaying the session log derives the phases for free and keeps the PC preview consistent; only the unsubmitted edits need localStorage.
