# Agent Note: 移动端 v5 —— AI Workmate 信息架构、v:3 报告围栏与工作存储的本地/日志边界

Status: implemented

[English](2026-09-22-mobile-v5-aiworkmate-ia.md) | 中文

## Problem

到 v4 为止，移动端是两 Tab（消息/我的）的纯聊天面：v1 工作台/数据 Tab 的问答职责早已折叠进聊天同事，但答案无处沉淀——风险清单或经营概览在滚动里蒸发，「让 AI 办」没有可挂靠的工作对象，执行过程不可见。信息架构需要的是一个工作域，而不是更多聊天；且这个域的数据必须守住「模型可见 ⟺ 日志可重建」红线，又不把 UI 状态灌进模型上下文。

## Decision

**十路由四 Tab。** v5 壳分发十个 hash 路由——`#/`（home，默认落地）、`#/chats`、`#/chat/:id`、`#/work`、`#/work/:id`、`#/me`、`#/tasks`、`#/files`、`#/agents`、`#/login`——挂在四 Tab 栏（AI同事/对话/工作/我的）后。TabBar 只在四个白名单页渲染；chat 与工作详情是全屏层，任务/文件/AI 同事目录是二级页。首页承接「今天有什么等我」：今日台账统计卡、快捷任务 chips、同事横滑、过滤工作会话后的最近对话。

**第三代折叠落点按语义归位。** 旧 hash 头重新落地：workbench→work（工作台的语义归宿是工作 Tab）、contacts→agents（v2 通讯录的职责——发起同事会话——由 AI 同事目录承接）；messages/data/kg→chats 与 profile→me 维持二代落点。旧深链（含 PC 预览 iframe）落到活页，不落死 Tab。

**报告围栏沿用 v:3。** report 载荷（id/title/subtitle/metrics/rows/table/actions）是既有 `v:3` 信封下的第七种 `dsh` 围栏载荷，而不是升 `v:5`：信封版本标记的是协议代际——围栏 + 信封 + type 判别 + 失效降级——新载荷类型不改变其中任何一项。严格等值检查意味着升版本要么六种既有载荷全部跟升、要么引入双轨判别，收益为零；旧客户端遇到未知载荷类型与遇到错误版本走同一条降级路径，两种方案的向后兼容完全相同。条数上限（metrics 1–6、rows ≤8、table 列 ≤5 行 ≤10、actions ≤4）是 persona 契约的一部分：超限整卡降级为可见的折叠原文，优于前端宽容截断后静默丢失模型产出。

**工作存储是本地态；模型可见事实走真实 user 消息。** 工作项（todo→doing→review→done，状态机守卫）存 localStorage，绝不进会话日志——高频 UI CRUD（状态翻转、收藏）留在模型上下文之外。模型必须看见的每个事实都以真实 user 消息落 durable log：M1 向源会话发创建通知、M2 向隔离执行会话发执行指令、M3 完成通知、M4 返工指令，以及报告卡的 send 动作。纯 UI 移动（view/link 跳转、弹层开关）不写任何东西。执行会话隔离集合同样是本地登记（会话列表按 id 集过滤），不是日志属性——跨设备回放无法重建它；记为已知限制，而不是要用写日志修复的缺陷。

**两态藏在同一数据源接口后。** 工作详情页消费 TimelineDataSource；真实态把执行会话的轮询历史折叠为步骤与结果，演示态推进脚本序列——同一组件、数据源切换。模式判定：Profile 显式开关优先，否则一次 `llm.models` 探测（目录含可用模型即 live），任何失败都 fail-safe 落演示——演示绝不冒充真实。实现期校准点裁决为保留探测：`llm.models` 语义与设计一致。演示 seed 项全部带 demo 标记，「清除演示数据」只删它们。

## Consequences

- 登记流程与报告流程经 persona 教学双向互斥（登记永不 report；报告回答永不 draft）——模型无法在一条回复里混用两种卡族，围栏保持一条回复一收尾。
- 未来载荷类型加入 `DshPayload` union 不升信封版本；只有信封结构变化才 bump `v`。
- 工作数据不跨设备同步——本地存储的代价——而会话日志保持完整，M1–M4 审计链在工作项消失处依然存活。
- FilesView 的「最近文件」分区按设计的字面去重语义恒为空，渲染固定空态文案，待该设计问题裁决。

## Alternatives considered

- **恢复 v1 工作台/数据 Tab。** 拒绝：v2 已把问答职责折叠进聊天同事，恢复 Tab 是职责回退。工作域以工作 Tab 加二级页承接，而不是平铺聊天 Tab。
- **report 用 `v:5` 信封。** 按上述代际论证拒绝；双轨判别的寿命会在下一种载荷类型到来时立刻过期。
- **工作项写会话事件。** 拒绝：状态翻转与收藏是 UI 状态，写日志会把界面噪声灌进模型上下文；只有用户意图消息（M1–M4、send）是模型事实。
- **流式执行时间线。** 本批拒绝：移动端新鲜度处处是轮询模型，真实态时间线复用 readHistory 折叠；流式是后续独立工作。
