# Agent Note: W3-B5 organization & permissions (department tree + affiliations + role×collection matrix + department-routed approval)

Status: implemented

English | [中文](2026-09-27-w3-b5-org-acl.zh.md)

## Problem

User feedback:「得有部门员工的一整个权限管理吧」. The platform had no org structure (no departments, no user affiliation), roles were admin/root/b4guard plus a member policy of `view`-only grants, and the approval engine's `approver_map` resolved usernames only (W2-B5) — an approval tier could not be routed to「质检部 whoever is on duty」, and an administrator had no page to see or govern what each role may do per collection.

## Decision

- **No org_departments/org_employees is ever built — plugin-departments owns the whole org plane.** The snapshot's plugin (enabled since setup) provides the `departments` tree (adjacency list, `parentId`), the `departmentsUsers` through table, `users.mainDepartmentId` (auto-synced by the plugin's afterSave hook on every affiliation write), and a full native management page under 系统设置 → 用户权限 → 部门. The seed (nocobase-w3-org-acl.mts) plants 新源食品集团 → 采购部/计划部（PMC）/生产车间/质检部/仓储部/销售部/行政人事部 plus the deliberately member-less 储备人才池 (the empty-department negative fixture), attaches the existing demo users (quality_lead + the new qc_inspector → 质检部 so department routing expands to a real two-person tier), and backfills `hub_hr_employees.org_dept` (a new m2o → departments) so the roster page shows the org department while departments/users stay the single source of truth (the legacy `department` m2o → hub_hr_departments stays untouched — f3's demo surface).
- **The 权限矩阵 page renders the matrix read-only; the write face is NocoBase's own role editor.** A JSBlock reads `rolesResources`/`rolesResourcesActions`/`roles` through three MultiRecordResource instances and renders role × collection × view/create/update/destroy/export as ✅/— (the D7「只读渲染 + 表单直写」split). rolesResources and rolesResourcesActions are plugin-acl's private collections — absent from the collection manager, so any v2 table/form block on them renders the「可能已被删除」placeholder — therefore the direct-write face is the native editor (系统设置 → 用户权限 → 角色), which the page footer names; the JSBlock data plane reads them fine once view/list/get is granted.
- **member's business action matrix lands as rolesResources rows, grants before probes (PLAN risk ④).** view/list/get ride the B1 grants; create/update join per domain — pur_*, wms document collections (receipts/shipments/transfers/counts), qm_inspections/qm_inspection_readings (+ qm_nc_dispositions update), mfg execution collections, so_orders, and wfl_approval_todos update (the act path). Engine-owned ledgers (wms_stock, wms_movements) and every destroy/export stay admin-only. The 403-flip probe proves the matrix bites: narrowing (admin, wms_counts) to view/list/get makes b4guard's empty-body update refuse 403; re-adding the full action set plus one touch-update restores 200 with zero rows left behind.
- **Department routing extends approver_map without touching the pure path (缺省零漂移).** A role value may now be `{type:'department', value:'质检部'}` (or mixed with usernames in an array). `resolveApproversOfRole` (approval-engine.mts) expands the department to its member usernames through departments/departmentsUsers and hands plain username maps straight to the shared pure `approversOfRole` — same map, same arguments, same order as W2. Unknown departments and member-less departments fail loud at submit; the selftest pins the pure-map expansion shape (two rows, one per user) as the zero-drift assertion. qm_nc_dispositions' manager tier now routes to 质检部 permanently through the B4 config-center channel (REST + config_note audit); its witness disposition's todos expand to quality_lead + qc_inspector and one member's act completes the whole tier (W2 OR-sign-off semantics). The nb_approve tool path still resolves pure maps only — a department entry fails loud there, so department forms belong to page/CLI-driven document types.
- **B4's consistency probe understands the department form.** assertWflConsistency's approver-existence check resolves `{type:'department'}` entries against departments/departmentsUsers (existence + non-empty) instead of silently skipping them; the B4 map summary renders「部门·质检部」labels; the approver_map form description documents the form.

## Consequences

- A real operator can maintain the org (native settings page), see it (the 组织架构 page's SVG chart with #id labels + departments/users tables), and govern per-collection actions from one page; the employee roster shows each person's org department.
- The approval engine can route a tier to a department without naming users; staff changes in departmentsUsers re-route future documents with no config edit.
- member users gain real business write actions in their domain while the ledger bypass guards and destroy/export stay admin-only; the flip probe plus verify's no-leftover assertion keep the guard honest.
- setup-nocobase verify imports `collectOrgAclFailures` from the org-acl script — one 口径 for the tree/affiliation对拍, page wires, admin-only matrix menu, member action floor, the dept-routing witness, and the (now department-aware) B4 probe.

## Notes (pitfalls found live)

- **plugin-acl writes the runtime ACL only on `rolesResources.afterSaveWithAssociations` and `rolesResourcesActions.afterUpdate`.** There is no afterDestroy listener (a destroyed resource row leaves the narrowed runtime face alive) and an action-row CREATE writes nothing through — after granting actions you must touch one action row (an update) to make the rewrite re-read them; the 403-flip probe and every grant helper end with that touch.
- **An action row whose `fields` is `[]` hides every column** (list answers 200 with zero rows) — the B1 "explicit full field lists" convention only applies where the collection manager actually has field rows; when it does not, leave fields null and never write an empty array.
- **The pm.departments snippet declares configurable actions; it grants nothing.** The admin role's strategy carries create/view/update/destroy/export/importXlsx — no list/get — and the root user's only role is root with a null strategy (everything rides explicit resource rows). The org chart therefore grants view/list/get on departments/departmentsUsers to admin/member/root and on the three ACL collections to admin/root; without those the JSBlock dies mid-render on a 403.
- **Private plugin collections cannot host v2 blocks.** departmentsUsers and rolesResources/rolesResourcesActions exist in the DB and answer REST, but the collection manager has no row for them (collections:create refuses "already exists"), so table blocks render the deleted-placeholder — edit those planes through their plugin's own UI or the REST channel.
- **A browser session's role is a header, not a guess.** Page-internal fetches without `X-Role` answered 401/empty mid-diagnosis and an expired session made every render look broken; probe with `X-Role: <role>` + a fresh bearer token before blaming the wire.
- **destroyDepartmentCheck refuses deleting a department that still has members** — the title-less install-residue rows (#4/#6, both holding zhaoxiaofang) survive the sweep; they render as two blank rows in the departments table and are filtered out of the chart (kept as a W4 cleanup once the stale affiliations move).
- **Repeated builds duplicated the roster column** — the org_dept existence check matched the column but the rebuild-after-rollback cycle still minted three; swept by destroying the extra TableColumnModel rows (kept one). The users-table `mainDepartment.title` column path renders nothing through the v2 column wire and was dropped in favor of the chart's #id mapping.

## Alternatives considered

**Build org_departments/org_employees ourselves.** Rejected (PLAN D7, capability inventory §4): the plugin's collections, sync hooks, and management page already cover the plane; a second roster forks the truth.

**Direct-write tables on rolesResources/rolesResourcesActions for the matrix page.** Rejected by the platform, not by preference: private collections cannot carry v2 blocks. The native role editor is the write face; the JSBlock is the visualization.

**Route departments inside nb_approve too.** Deferred: the tool path shares the pure rules module, and threading IO-free department expansion through it means widening the tool's data access; qm_nc_dispositions (the department-routed flow) is page/CLI-driven, so the boundary is documented instead.
