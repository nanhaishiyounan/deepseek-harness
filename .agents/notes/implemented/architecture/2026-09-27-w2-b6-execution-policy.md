# Agent Note: W2-B6 execution policy — MO-level kit policy, over-issue ratio, and the FCS split-suggestion card

Status: implemented

English | [中文](2026-09-27-w2-b6-execution-policy.zh.md)

## Problem

99-legacy #5/#6 (the B6 halves): the kit check was all-or-nothing — `postIssue`'s `reservation_state='assigned'` gate made a partially-starved MO unable to issue its covered components (urgent orders needed a warehouse-side workaround), and over-issue was refused outright (cumulative issue vs the reserved demand). The FCS day-bucket engine left a cross-day operation stuck at the overload note's plain text (the W-round D5 contract wording) with no structured advice. Batch 06-b6 requires both policies configurable at the MO level with the W-round behavior as the exact default, and the overload advice upgraded to a structured 拆单建议卡.

## Decision

- **The config seat is two MO-level columns, not wfl extras and not cordis.yml (PLAN D8).** `mfg_orders` gains `kit_policy` (select full_lock/partial_allowed, default full_lock) and `overissue_ratio` (float [0,1], default 0). Rationale: the policy is an execution-domain attribute of one order — an urgent order opts itself in without touching any global switch; the wfl `extras` seat stays approval-domain (B5). Both columns land additively: w5's collection definition carries them for fresh installs, w6's `MO_COLUMNS` grows them for existing trees (fields:create when missing) plus a one-shot backfill of existing rows to full_lock/0 — the engine additionally treats NULL as full_lock/0 (`moKitPolicy`/`moOverissueRatio`), so mrp-run MOs minted without the columns stay compliant (the verify gate tolerates NULL and refuses every other out-of-domain value; negative/NaN ratios fail loud at the first engine touch).
- **partial_allowed is a new non-blocking kit state, not a loosened gate.** `availabilityCheck` under partial_allowed records `reservation_state='partial_allowed'` (a fourth axis value, distinct from full_lock's blocking `partial`); covered components keep their hard reservations exactly as before, the shortfall ladder (component/gap/ETA) stays complete in `kit_data` (which now also carries the policy), and a full miss still reads `none`. `postIssue` admits `assigned` always, plus `partial_allowed` when the MO opted in — an uncovered component still refuses on its missing reservation (未齐组件无预留), and `MO_EXECUTING_STATES` never loosens with the policy (an approved-but-unreleased MO refuses both kit and issue).
- **The over-issue ceiling is reserved × (1 + ratio); ratio 0 keeps the W-round refusal.** `postIssue`'s cumulative check rides `issueCeilingOf(reservedQty, ratio)`; a posting that rode the headroom appends `超领 N（overissue_ratio r）` to the issue row's note (the 100×1.05=105 hand calc: a single 106 against the intact reservation refuses with the ceiling spelled out, 105 posts with the 超领 5 note).
- **The FCS advice is a structured card under the never-straddle scope (PLAN D9, option B).** `SlotDecision`/`PlannedOperation` gain an optional `suggestion` — `buildSplitSuggestion(wc, minutes, capacity, earliestStart)` answers `{ kind: 'split_suggestion', minutes, capacity, suggestedSplits: ceil(minutes / floor(capacity × 0.9)), perSplitMinutes: floor(capacity × 0.9), earliestStart, note }` (1200 min vs a 480-min day → 3 splits × 432 min); both the forward and backward overload branches carry it, and the negative-slack backward plan answers with the `expedite_suggestion` card (改期/拆单/外协). The note keeps its human-readable form (W-round wording plus the concrete split numbers) — the mobile card renders the note, the Preview panel and `preview_data` carry the object. The 口径 (operations never straddle days; oversized operations get split advice, humans split the MO) is declared in three places: mfg-schedule's module header, the 排产看板 heading (flowModels title updated; see Notes), and the overload note itself (the batch doc's fallback clause).
- **Page increments mount as standalone flowModels rows (the n18ai- isomorph).** The two policy columns land on the already-built 生产订单 and MO 执行视图 tables as `w2b6-`-prefixed TableColumnModel rows (idempotent by fieldPath); the reservation_state enum is re-written with partial_allowed. A light `--rollback-w2b6` (the w2b6- prefix key) undoes exactly this batch — columns, enum, page rows, heading — without touching W-round data.
- **Re-seed guards harden w6's stock idempotence.** This batch's w6 re-run exposed a latent hazard: `binBy('SH-A-02-07')` returning undefined made `Number(undefined)=NaN` mint an empty-shell bin row and silently double the stock (breaking `stock == Σmovements`). seedRows now skips re-seeding a component whose bin row is missing, and skips one whose seed RECEIPT already rides the ledger while its stock row is gone (environment damage — never auto-repaired), each with a loud log line.

## Notes

- **The CreateForm grid tree cannot grow fields in place.** flowModels:get does not return the embedded `subModels` tree, so re-saving a CreateFormModel to append FormItems would overwrite and lose the grid; editing the two policy fields stays with the column defaults (new rows mint full_lock/0) plus REST — recorded here as the deliberate deviation from the batch doc's「表单加两字段」wording.
- **The 排产看板 heading update lands in flowModels but the running front end keeps rendering the old block title** (a schema-aggregate cache; a hard reload does not bust it). The 口径's three declaration seats stand at the data level (module header JSDoc, the updated flowModels title, and every overload note — the note renders live in the 排产看板 table), so the fallback clause covers the page; the heading will appear when the platform next rebuilds its client cache.
- **The over-issue acceptance reads as single-shot semantics.** postIssue consumes the reservation per posting, so the「cumulative 106」hand calc rides the intact-reservation single 106 (the honest branch); after a 105 posting consumes the reservation, any further issue refuses on the missing reservation — a W-round shape this batch does not change. The evidence driver re-verifies only the durable trail (posted 105 + note + the refused row still draft) on re-runs.
- **The ledger drift this batch surfaced and repaired:** the w6 re-seed doubled VEG/DMP-PKG stock against their single seed RECEIPT legs; the repair deleted the duplicate/naN-bin rows, backfilled the missing SH-A-02-07/08 bin rows, and restored the movements-derived projection (DMP-PKG 19695 source + 305 WIP = 20000) — `--assert-ledger` and `--recalc` both green afterwards. The MO-2026-0002 reservation's 16160 allocation ledger went with the deleted corrupt row (the reservation row itself survives; the demo MO stays partial and unissuable, which is its W-round design).
- The demo MOs (MO-W2B6-00A/00B/00B2/01/02/03/05 + BOM-W2B6-DEMO/FULL/LONG + WC-W2B6) stay in the tree as live page material; the negative-ratio probe MO is destroyed after its fail-loud evidence (verify's default-value gate stays green).

## Alternatives considered

- **Global kit-policy switch (site-level) or wfl extras as the seat** — refused (PLAN D8): the policy varies per urgent order, not per site or per approval flow; the MO row is the only seat that scopes the relaxation to exactly the order that needs it.
- **Cross-day continuous scheduling for oversized operations (option A)** — refused (PLAN D9): the day-bucket algorithm's core rewrite risk outweighs the value; the never-straddle boundary is the ERPNext-official isomorph, and the structured card plus the explicit 口径 declaration keeps the boundary honest instead of hiding it.
- **Cumulative-multi-issue over-issue demos** — the honest reading: postIssue consumes the reservation per posting, so a post-consumption「cumulative」refusal is really the missing-reservation branch; the acceptance rides the intact-reservation single 106 instead of staging a fake two-leg cumulative.
- **In-place CreateForm field append** — refused: the embedded grid tree is unreadable through the API and a blind re-save would drop it; column defaults + REST editing cover the acceptance without the risk.
- **Silent fallback on a corrupted policy/ratio value** — refused: only missing/empty falls back to the W-round default; a present-but-illegal kit_policy or a negative/NaN ratio fails loud at the first engine touch (misconfiguration fails loud).
