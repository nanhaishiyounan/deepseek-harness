# Agent Note: Batch 2 quality-face closure — snapshot desyncs, a ghost fixture package, the lint 900, and timeout triage

Status: implemented

English | [中文](2026-09-08-batch2-quality-face-closure.zh.md)

## Problem

After batch 1 of the boot-chain diagnosis ([plans/diagnosis-2026-09-08.zh.md](../../../../plans/diagnosis-2026-09-08.zh.md)) fixed F1–F3, five quality-face groups remained red: F7 tool-catalog spec expecting 79 tools where 81 register, F8 THIRD_PARTY_NOTICES.md out of sync, F5 verify-cordis-config flagging `examples/package.json` for missing `@deepseek-ai/dsh-fake-llm`, F6 ~900 lint errors (the handoff's stash check had only removed the N/V lines — not an empty baseline), and F9 22 timeout failures in the full test run. Each group needed triage (real defect, stale snapshot, or environment) before any fix, with 343 uncommitted workspace changes protected from stash/reset.

## Decision

### For desyncs, first ask which half failed to follow — do not blindly edit expectations

F7's `verify-tool-catalog` was already green: V4 had regenerated `docs/tool-catalog.md` but missed the hardcoded expectation list in [`gen-tool-catalog.spec.ts`](../../../../packages/core/tools/tests/gen-tool-catalog.spec.ts); the tools genuinely register and stay model-visible, so the expectation list is what updates. F8 was an unregenerated artifact: one `pnpm run gen-third-party-notices` pass added all 7 missing entries (the graphology trio from the graph page; pdf-lib/exceljs/duckdb from the delivery lines). Both rulings turn on which side is current — the authoritative generator/registry or the committed snapshot.

### Ghost package names never enter the manifest: fixture rows carry only resolvable bare names

F5's `@deepseek-ai/dsh-fake-llm` has no workspace package — the implementation is injected through the `loader.internal.import` stub map in [`kg-tools.spec.ts`](../../../../examples/kb-agent/tests/kg-tools.spec.ts), and the fixture row only places an llm provider in the Loader graph. `verify-cordis-config` requires bare plugin names under examples/ to resolve from `examples/package.json`, and adding a `workspace:*` entry there would break pnpm install. Fix: drop the fixture row and mount the module directly with `context.plugin(FakeLlmModule)` before loader assembly — same process, same context, an equivalent service registration, snapshot unchanged.

### The bulk of lint 900 is artifacts, not code: classify before touching anything

903 = 847 + 56. The 847 errors sit in 14 `src/*.d.ts` files (emit artifacts carrying sourceMappingURL): all untracked, all with the mtime of one incident, and not regenerated by the day's `build:lib:host` — delete them, do not fix them (repairing semicolons in artifacts inverts the problem). The 19 tracked `src/*.d.ts.map` files show the same incident once escaped into a commit (`.gitignore`'s `.map` rule cannot touch already-tracked files). The 56 real-source errors all live in this round's working-line files (zero baseline red): `--fix` cleared 25, hand fixes cleared 31 — non-null assertions became narrowing/optional chains, and the four genuinely exceptional shapes (constructor-shaped WebGL enum stubs, tests whose subject is a non-Error rejection, async as the method table's Promise-return adapter, assertions oxlint's lightweight types disagree with) take line-level `oxlint-disable-next-line … -- reason` comments, with `.oxlintrc.json` left untouched.

### Timeout triage by shifting sets plus per-file reruns

Two full runs (one alongside lint, one alone) failed 30→23 with disjoint newcomers — a drifting failure set already rules out real defects. All 24 files that ever failed have a PASS rerun on record (most passed first try; oxlint-contract failed once then went fully green — a spawn-cold-start flaky). Under vitest's 12-thread whole-repo concurrency, the 5s default timeout is a structural local ceiling for tests that spawn subprocesses; these are registered environment reds, and a local full-run EXIT=0 is not the target.

## Alternatives considered

**F5 via a manifest entry or by renaming to `dsh-llm-replay`.** The former breaks pnpm install (nothing to resolve); the latter makes the fixture claim replay while a stub swaps in the fake — a semantic lie. Direct mounting is the honest shape: the provider never passes through the Loader, so it needs no resolvable name at all.

**F6 by repairing 847 `.d.ts` semicolons.** Rejected: those files are build-incident residue whose correct state is nonexistence; fixing lint line by line would pin the garbage into the workspace.

**F9 by raising vitest's default timeout.** Rejected: that reshapes test infrastructure around one machine's load while CI owns the matrix; the local evidence chain (per-file PASS reruns) is the right record.

## Consequences

- End state: `pnpm run typecheck` 0; `pnpm run lint` 0 warnings 0 errors; `pnpm run verify-cordis-config` 178 files passed; `pnpm run doc-sync` 28/28; full test run 15884 passed / 23 environment reds (each with a recorded PASS rerun).
- From here on, bare plugin names in examples fixtures must name real workspace packages; test-injected fake providers mount through `context.plugin()` directly.
- `--fix`'s `no-unnecessary-type-assertion` can delete button assertions the testing-library `getByRole` overload requires, based on its lightweight types — every lint fix pass must be adjudicated by typecheck, with deleted assertions restored behind a line-level disable.
- Follow-ups (later PRs): `git rm` the 19 tracked `src/*.d.ts.map` files; the `{{t("Roles")}}` keys inside the NocoBase iframe belong to the platform/nocobase snapshot and stay untouched per the isolation rule.
