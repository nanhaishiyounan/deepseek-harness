# Agent Note: W6-R4 sourcing repair round — lead-N/A scoring, the broken error feedback chain, award audit, and the read fence

Status: implemented

English | [中文](2026-10-02-w6-r4-sourcing-fixes.zh.md)

## Problem

W6-B7 verification failed at 86/100 with five BLOCKING defects across four files: the scoring core `w6b7-sourcing.mts` (`num(null)=0` scored an unreported lead time as 0 days and poisoned min-lead, handing every valid supplier a lead score it did not earn; the submit `catch{}` swallowed failures silently while the idempotent early return stranded the PO on draft forever), the matrix JSBlock `w6b7-blocks.mts` (`loadMatrix` had no catch, so a nonexistent RFQ produced zero on-page feedback; the award modal showed the internal id「报价行 #N」; a double-click race dumped the raw 409 text into the note), the engine routes `approval-engine.mts` (GET `/sourcing/*` checked login only, letting sales_rep/finance read every supplier's pricing; the outer catch attached CORS to `/recall/` and `/label/` alone, so cross-origin `/sourcing/*` error responses were masked into fetch failures by the browser), and the PO detail page rendering no snapshot at all (`compare_note` was persisted but never shown). Five ADVISORY items (modal information density, race wording, no per-RFQ won-quote uniqueness on `pur_quotes`, overwrite-only `updated_by` on the weight row with no audit trail, a dead span back-link) and three truth debts (the note's「assert 17/17」versus a measured 14, an unlabeled excerpt in gates-b7.log, one vacuous assertion at `w6b7-verify.mts:172`) completed the batch.

## Decision

- **Lead N/A (TC-08)**: `rawLead()` classifies null/undefined/`<=0`/non-finite as "not reported"; min-lead is computed over the valid subset only; a null row carries `lead_score=null` / `lead_time_days=null`, drops the axis from the weighted total, and renormalizes through the same present-axes mechanism as a missing quality scorecard, with the formula text reading「交期分=N/A」. Two `MatrixRow` fields widen to `number | null`; an award to a winner that reported no lead omits `expected_date`, and the ladder text shows「交期N/A」.
- **Error feedback (TC-17)**: `loadMatrix` gains a try/catch covering both fetch rejection and `ok:false`, clearing the stale matrix and writing「RFQ 不存在或已关闭」into the note; the engine's outer catch attaches `RECALL_CORS` to every API-route error response (static HTML surfaces exempt) and adds `code`/`message` fields; `sourcingRoute`'s `fail()` takes a code, and the matrix route maps an unknown RFQ to 404 + `rfq_not_found`.
- **PO snapshot**: `compare_note` gains「定标时间」(from the transactionally stamped `awarded_at`); each PO swimlane card renders a「定标快照」`<details>` with the full `compare_note` (weights/formula/awarder/time), its data source proven to carry the full text through the NocoBase REST list.
- **Award audit + non-silent submit**: `pur_award_audit` (award_id/actor/action/payload/ts with actions award/replay/resubmit/submit_failed); the status CAS, winner/loser flips, and the audit insert land as one data-modifying CTE (won/lost gated on `EXISTS (SELECT 1 FROM moved)`); `pur_rfqs` gains `awarded_at TIMESTAMPTZ` via idempotent migration with backfill; a submit failure logs a `console.warn` plus a `submit_failed` audit row; the idempotent early return now resubmits a draft PO (writing a `resubmit` row).
- **Read fence**: `assertSourcingReader` (采购部/admin/nocobase may read; sales_rep/finance get 403 `read_fenced`) shares the `procurementUsernames()` query with the stricter write fence.
- **ADVISORY**: the modal resolves supplier/unit-price×qty/lead/total/rank from the matrix row; 409 and CAS clashes both map to 409 with the「已定标（双击/并发竞态被引擎拒绝）」note; `ux_pur_quotes_won_per_rfq` partial unique index on `(rfq_id) WHERE is_won` (the `ux_crm_quotes_converted` precedent); `pur_sourcing_weight_audit` appends old→new+actor per change; the back-link chip becomes an `<a href=比价表?rfq=…>` and the matrix block preselects the RFQ from `window.location.search`; the empty state distinguishes「暂无可比价询价单」.
- **Truth debts**: the B7 note's「17/17」corrected to the measured 14/14 (20/20 after R4); gates-b7.log's header now labels the excerpt and points at the full logs; the vacuous assertion became a byte-identical DB↔matrix round trip proving the JSON layer neither evaluates nor escapes. Four change-surface misstatements were also checked: no `/scm/*` route exists anywhere in the repo (grep zero hits), `approval-rules.ts` does not exist, and `w6b4-bomver` belongs to the W6-B4 batch (gates-b4.log:2448) — the B7 note's scope line never claimed any of the three, so the misstatements lived in the batch handover narrative, recorded here as verified.

## Consequences

The demo leg passes all 13 sections (leg 0-10; new: leg 5b read fence, leg 7b submit-failure trail + idempotent resubmit, leg 9 lead N/A, leg 10 the 404+CORS pair) and the assert leg 20/20; the b2 regression stays green. TC-08 is pinned on three states: for lead=(null,7,14) the 7-day supplier scores 100, the 14-day 50, and the null row N/A with a price-only total (no scorecard). A submit failure is queryable on both sides — the `pur_award_audit` `submit_failed` row and the engine log's `[sourcing] PO … 送审失败` warn (w6-r4-engine-boot.log); a replay drives the draft PO to pending. Evidence: `demos/acceptance-w6/w6-r4-01..11-*` (demo/assert logs, the psql audit reconciliation, the read-fence curl trio, and the TC-08/404-toast/modal/double-click/PO-snapshot/back-link screenshots) plus `w6-r4-shot-meta.json`. Known residue: after a `flowModels:save` code upgrade, the SPA may keep executing the previous JSBlock code for minutes (the surface GET already serves the new code, and a reload resets the wait) — the evidence script polls silently for four minutes; harmless in production, but anyone iterating on blocks should know. The `MATRIX_PAGE` route uid is a constant baked into the po-board block code and must move with a page rebuild.

## Alternatives considered

- **Score an unreported lead as 0** — the original implementation the verification rejected: 0 days is the best-possible lead, rewarding the supplier that never quoted one.
- **Roll back the award when submit fails** — the CAS and the loser dispositions have already taken effect externally; a rollback needs compensating writes. A durable trail plus idempotent resubmit preserves traceability at minimum cost.
- **Insert the audit row after the PO mint** — loses the same-transaction atomicity with the status move, which is exactly what lesson 24 asks for.
- **Reuse the write fence for reads** — locks the matrix away from the nocobase integration account and misclassifies legitimate read-only access.
