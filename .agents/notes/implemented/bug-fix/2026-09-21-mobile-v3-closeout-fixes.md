# Agent Note: Mobile v3 close-out fixes — collapsed fence degradation, `{{today}}` prompt variable, persona table-name discipline

Status: implemented

English | [中文](2026-09-21-mobile-v3-closeout-fixes.zh.md)

## Problem

Real-API verification of the mobile v3 redesign ([evidence](../../../../plans/2026-09-21-mobile-v3-redesign/04-verification-evidence.md) §4) surfaced three shipped defects:

1. A `dsh` fence whose body failed protocol validation degraded to its **original fenced JSON rendered as the user-facing narrative bubble** — a single invalid field type (bare-number `rowId`, unknown `widget`, `null` system value) made the whole payload vanish and dumped raw protocol at the user, violating the v3 principle that protocol payloads are invisible in the visual layer.
2. The model had **no current-date input**, so the mandated `日期=今天` derivation hallucinated (`order_date=2026-05-14` landed in PG while the rationale said "today = 2026-09-21").
3. Inter-tool narration leaked internal `hub_` collection names ("我看到有 hub_po_purchase_orders 采购单 collection") although the persona already banned them from prose — the ban's scope did not clearly cover tool-call narration.

## Decision

**Degraded fences collapse, never dump.** [`splitMessage`](../../../../packages/client/ui-mobile/src/client/protocol.ts) now emits a distinct `degraded` segment kind (original fenced text carried along) instead of folding the invalid fence into the narrative; [`foldHistory`](../../../../packages/client/ui-mobile/src/client/fold.ts) projects it to a `degraded` chat item rendered by ChatView as a collapsed `<details>` summary row ("结构化消息（格式异常，已折叠）") whose body holds the original text. A message containing any `dsh` fence — valid or degraded — takes the v3 path, so a wholly-invalid fence can no longer fall into the v2 legacy narrative split; the v2 ```` ```json ```` draft path is untouched. `degradedCards` counting and the answered-state semantics (a degraded notice retires a pending ask, like any assistant-owned item) are preserved. A degraded notice also advances `contextChipsOf`, matching text/cards/receipts.

**The loop registers a `{{today}}` prompt variable.** `dsh-agent-loop` registers `today` beside `provider`/`model`/`cwd`, resolving per assembly to the host process's local calendar date in `YYYY-MM-DD` form — so a session crossing midnight renders the new date on its next step. The mobile form-assistant persona opens with 「今天的日期是 {{today}}」 and mandates that every `日期=今天` derivation take that value. [README.md](../../../../packages/core/system-prompt/README.md) and its Chinese counterpart list `{{today}}` in the shipped-variable set.

**Persona discipline scopes the table-name ban to every user-facing text.** The mobile persona's 正文纪律 now covers narration between tool calls, drafts, and receipts, permits `hub_` collection names only inside tool-call arguments and protocol fence JSON, and keeps the business-name vocabulary rule.

## Alternatives considered

**Coercing lossless payload variants at parse time** (numeric `rowId` → string, unknown `widget` → `text`, `null` system value → `""`). Deferred: it fights the model contract with silent fixups and cannot rescue structurally broken fences; the collapsed notice removes the user harm for every failure class at once. Coercion can still be added later for the specific variants the evidence documented.

**Injecting the date through apiproxy or a plugin on the mobile composition chain.** Rejected: the persona template already interpolates `{{model}}`/`{{cwd}}` through the loop-registered variables, and "what day is it" is a session-intrinsic fact every composition shares — a per-chain injection point would duplicate the mechanism and leave other presets without the variable.

**A static persona line ("ask or use the server default when unsure of the date") plus expanded date fields on the draft card.** Rejected as the primary fix: it concedes the derivation promise instead of keeping it; kept only as the persona's fallback wording if the variable were ever unavailable.

**Filtering `hub_` names out of narration in the client fold.** Rejected: the client cannot reliably distinguish a table name from a business phrase, and scrubbing text client-side hides the model-behavior problem instead of fixing it at the prompt.

## D2 acceptance follow-up (2026-09-22 batch)

Real-model D2 verification failed five Important and one Minor item; each fix landed with its test:

1. **Fresh-session identity (N1).** The first `session.list` read after `session.create` races the create, so the chat header and welcome card fell back to the local-session visual until a refresh. [`createSession`](../../../../packages/client/ui-mobile/src/client/sessionsService.ts) now records the create response's `agentPreset` echo in a pending map, and ChatView reads it until the list row lands — the create echo exists exactly to label without a refresh.
2. **System numbers never land blank (N2).** The persona let the model generate `po_number` at write time and model variance sometimes skipped it (batch id=16 landed empty). The new [`systemFields.ts`](../../../../packages/client/ui-mobile/src/client/systemFields.ts) generates registry-declared numbers client-side — max same-year suffix +1 over the collection's live rows, a clock-derived fallback when the read fails — cached per draft id so revisions keep one number; `mergeCardValues` folds the number and the client-calendar date into both the card display and the `form_confirm` fields, and the persona now mandates passthrough of a non-empty confirm value.
3. **Display-side leak sanitization (N3).** The persona ban stayed primary but proved insufficient under model variance (single-session leaks: `hub_po_items（product_name/qty/unit_price）`, `supplier_id=7`, ask-option hints). [`sanitizeBizText`](../../../../packages/client/ui-mobile/src/client/messages/rich.ts) maps identifiers through the registry's bounded business vocabulary, degrades unmapped `hub_` names to 业务记录, and drops a parenthesized group still carrying an identifier; narratives and ask question/label/hint render through it. This supersedes this note's earlier rejection of client-side filtering: the mapping is a closed dictionary over registry vocabulary, not open-ended text guessing, so the earlier "cannot reliably distinguish" objection no longer applies — the guarantee the user never sees an identifier is now enforced at the surface.
4. **Protocol fence names never render as tool rows (N4).** A model emitting `ask_field_pricing` as a (nonexistent) tool call rendered `✕ ask_field_pricing`. The fold marks protocol-named calls (`ask_*`, `form_draft`, `form_confirm`, `reject_flow`, `submit_receipt`) as protocol rows that render one fixed status line (补充信息… / 正在登记…) with no name and no failure mark.
5. **Turn-level avatar (N5).** Fold-split segments of one AI turn each repeated the avatar+seal (7+ per screen). Only the first assistant-owned item after a user item renders the avatar column; continuations render a 32px ghost column that keeps alignment — the adjudication line added to [03-visual-design.md](../../../../plans/2026-09-21-mobile-v3-redesign/03-visual-design.md) §4.1.
6. **`order_date` = the client's day (Minor).** The `{{today}}` chain was verified end-to-end (the loop resolves the host-local date; the dev host shares the browser's zone); batch id=16's off-by-one was late-night verification variance plus model drift. `mergeCardValues` pins an unedited derived `今天` date field to the client calendar date, making the landed value deterministic regardless of model drift. The first live re-run still landed `order_date` empty: the model invented column names (`po_date`, `total_amount`) the collection does not carry — the registry named only `po_number` explicitly, and that was the one column that landed. The persona now states each live table's exact writable columns (`hub_po_purchase_orders`: supplier_id/order_date/status/total/po_number, plus a `hub_po_items` detail row after the main row; `hub_po_suppliers`: name/contact_name/email/rating/status with `supplier_code` draft-display-only), forbids invented column names, and fixes the receipt summary to always carry 日期 and 单号. The final live run landed `order_date`/`total`/`po_number` all non-empty (PG rows id=18/19).

## Consequences

A malformed fence now costs one collapsed summary row instead of a protocol dump; the original text stays reachable behind the details toggle for diagnosis. The strict-variable contract means a persona referencing `{{today}}` fails its turn loudly when composed without the shipped loop — the same fail-loud rule `{{cwd}}` already follows. The landing guarantees (non-empty system numbers, client-calendar 今天 dates) are surface-owned: the confirm fence carries explicit values and the persona passes them through, so the write path no longer depends on the model inventing them. Unit tests cover the pending preset, the protocol-row folding, the sanitizer, the number/date merge, and the render branches (one avatar per turn, neutral protocol row); coverage stays per-file 100% on every touched file. The final live acceptance run (fresh session → fuzzy opening → fork ask → three-tier draft → confirm → receipt, 390×844) passed all eleven programmatic checks with `hub_`/protocol-name-free innerText and ten PNGs under [research/2026-09-21-mobile-v3](../../../../research/2026-09-21-mobile-v3). The earlier open item — a harness-side submit-receipt/nb-create consistency check — remains open, joined by two model-variance residues from the final run: a second draft revision can draw a fresh number the landed row does not use, and the optional `hub_po_items` detail row landed once with its `purchase_order_id` unset. The four registry forms without physical tables (`hub_qc_inspections`, `hub_wms_inbound`, `hub_wms_outbound`, `hub_fin_payments`) still carry registry-only field names until those tables exist.
