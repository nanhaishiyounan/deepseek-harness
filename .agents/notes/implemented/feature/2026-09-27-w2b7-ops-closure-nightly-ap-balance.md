# Agent Note: W2-B7 ops closure — the in-process nightly timer, the ap_balance mirror code, the AR/AP reconciliation page, and the report-fence self-check

Status: implemented

English | [中文](2026-09-27-w2b7-ops-closure-nightly-ap-balance.zh.md)

## Problem

Four W-round leftovers landed here (99-legacy #4/#12/#13/#14): the nightly chain (ROP scan / MRP close / KPI materialization / quarterly scorecard) depended on an external cron curling four routes because the open-source NocoBase snapshot ships no schedule plugin; the payable side had no KPI code (ar_balance existed, ap_balance did not — the pur_invoices/pur_payments data sat unmateralized); the mobile multi-metric board card intermittently collapsed into the degraded notice (a persona fence contract violation, 99 #12); and the b9 nine-step chain could not be replayed whole because stage 3 re-judged an already-judged QI order (single-shot semantics) and stage 7 re-shipped a terminal SO. Batch 07-b7 required all four closed plus the full-chain s1–s9 rerun green.

## Decision

- **The nightly timer is a plain `setInterval` in `serve()`, armed after `listen` only when `W1_NIGHTLY_ENABLED=true` (default off = zero drift: no timer logs, no automatic writes — the 80-second idle probe shows kpi_snapshots and mrp_suggestions byte-stable). No scheduler library: four idempotent verbs on a one-minute tick do not justify a cron parser, and the process marker (a date string in a closure) is exactly the state a single-process deployment needs.** A `>=` fire comparison plus the in-memory day marker means a restart may replay the same day once — every leg is idempotent (scanReorder dedupes by policy, runMrp opens a fresh run, snapshotMonthlyBalances and calcDay are destroy-then-create), so the replay is harmless and documented in the arm log.
- **Env validation fails loud at serve start whether or not the timer is on**: `W1_NIGHTLY_ENABLED` strictly `true`/`false`, `W1_NIGHTLY_AT` strict `HH:MM`, `W1_NIGHTLY_TZ` any IANA zone (validated by construction — `Intl.DateTimeFormat` throws on garbage). The checks run before the first NocoBase call, so a bad env dies before any side effect.
- **Leg order is scan-reorder → run-mrp → (month-end only) snapshot-month → calc-kpi, with calc-scorecard appended on quarter-start days.** The month-end snapshot leg sits before calc-kpi on purpose: the turnover pair reads `wms_monthly_balances` for the closing month, so a month-end nightly pass must materialize the snapshot before the KPI leg or the turnover rows cannot land that night. A failed leg logs and the next leg still runs (legs never block each other); the pass ends with a per-leg summary line. `POST /run-nightly` runs the same body once, manually, whatever the env says — and never marks the day, so the timer still fires on schedule.
- **ap_balance mirrors ar_balance exactly**: `Σ pur_invoices(invoice_amount WHERE match_result='confirmed' AND billed_at ≤ day) − Σ pur_payments(amount WHERE doc_status='approved' AND pay_date ≤ day)`, daily grain, board=business, money unit. Confirmed invoices are the AP confirmation state (the same state that opens the payment gate), approved payments are the settled outflow — draft payments never reduce the payable. The note on every snapshot row declares 业务台账口径，非会计核算 (PLAN D11 keeps the general ledger out of scope). A month with no confirmed invoice reads 0, not null (q4(0−0)); the acceptance hand-math closed both sides (AP 241,880−880=241,000; AR 280,820−256,000=24,820, where the 204,500 of future-dated crm_payments rows is correctly excluded by the paid_at ≤ day anchor).
- **The reconciliation page is a fifth w9 flowPage in the 经营分析 group** (board type widened to 'finance'): two per-code line charts through the same F4 authoring channel (ar_balance / ap_balance over calc_date) plus four read-only detail blocks (so_orders, crm_payments, pur_invoices, pur_payments). The setup-nocobase verify reads the chart filter through the server-canonicalized `{logic, items:[{path, operator, value}]}` form — the same read w9's `chartFilterValue` does; a bare `filter.kpi_code` read misses persisted rows. The 25-code floor and the mirror-diff gate (the two persona sources vs their `.dsh` mirrors must be byte-identical, the R4 r4-01 convention) also ride setup verify now.
- **The mobile degraded fix is persona text, three additions to both fence-bearing presets (business-advisor + mobile-form-assistant, source and mirror written together)**: an output-time self-check list (count every collection against the caps before sending), a violation→correction example (over 6 metrics → keep the top 4 and name the rest in one narrative sentence; over 10 rows → first 8 plus a "ask for the rest" note), and a two-step split-query guide (a wide「经营怎么样」question gets a ≤4-metric summary card plus send-style follow-up actions; the details belong to the second query). The renderer's contract (metrics 1-6 / rows ≤8 / table ≤5×10 / actions ≤4, no `"table": null`) is already enforced client-side — the persona layer now prevents the model from writing the violation instead of the UI collapsing it. The five-shot live probe (fresh sessions, 「经营怎么样」×5) rendered 5/5 report cards with zero degradedNotice collapses, each card ≤6 metrics with the split-guide visible in the actions; the single-metric OTIF turn also clean.
- **b9 chain replay guards**: stage 3 skips the inspect leg when the QI row's result is already ≠ pending (single-shot verdict kept, the replay proceeds — release-receipt was already idempotent); stage 7 skips the whole shipping leg when the SO is already shipped (the reservations were consumed on the first pass, so shipSo would die on 无有效预留) and asserts shipped_at non-empty instead of same-day — the first pass's date is the truth. With those two guards the whole s1–s9 chain replays green end to end.

- `runNightlySteps` is exported (like `parseNightlyEnv`, `tzNow`, `isMonthEndDay`) so a future selftest can drive the pure layer without HTTP.
- The reconciliation page's blocks[0] is so_orders, not kpi_snapshots — the w9 verify's dataScope wire loop finds no kpi table block under the page and continues by construction (`owned === undefined → continue`), so no special case was added.

## Alternatives considered

- **A cron-expression parser or a scheduler dependency (node-cron style)** — refused: the requirement is one daily fire with an env switch; a 60-second `setInterval` with a wall-clock comparison is the whole state machine, and the deployment doc says pick one scheduler (built-in timer or external cron), never both.
- **Firing only inside the exact HH:MM minute window** — refused: `>=` plus the day marker tolerates a busy or late-starting process (a serve booted after 02:30 still runs that day's pass once); missing a night entirely because the process was busy for sixty seconds is the wrong failure mode for an idempotent chain.
- **A persistent run-marker table** — refused: every leg is idempotent, so a restart replaying the same day is a no-op harm; a marker table would add a writable surface to an otherwise read-schedule concern.
- **Marking the day when `/run-nightly` runs manually** — refused: the manual route is an operator's verification tool; letting it suppress the night's scheduled pass would make the manual probe destroy the schedule it verifies.
- **ap_balance as a monthly-grain code (month-end rows only)** — refused: the batch doc's "月度" describes the reconciliation ledger's nature, not the grain; mirroring ar_balance (daily rows) keeps the two sides comparable on every date and gives the trend chart the same 90-day resolution the AR side has.
- **Counting draft pur_payments in the AP outflow** — refused: a payment request is not money out until approved (the W-round s7 chain approves PAY before it counts as settled); the note declares the approved-only anchor.
- **A renderer-side auto-trim (silently clip an over-limit card)** — refused: the card would show numbers the model never vouched for; the fence contract is the model's output discipline, so the fix belongs in the persona text (self-check + example + split guide), with the renderer's collapse staying as the last-resort signal it already is.
- **Making stage 3 unconditional again by resetting the QI row** — refused: the single-shot verdict is the quality engine's invariant (W2-B1 kept it); the replay guard skips, it never mutates a verdict.
