## Problem

B1 refused six advanced features at publish with B2-pointer messages (supervisorChain / formField / deptLeader / sequential / countersign / autoPass / assignUser); only 3 of the ten approval doc types had verified round-trips; the three approve entries (CLI / HTTP / nb_approve) forked side effects — the mobile entry had neither the so_orders/mps_plans effective hooks (BP-02) nor department-entry routing (BP-14); the config center's decoration title still promised「发布派生在 B1」; the page-callback workflow and engine-written audit rows formed a hidden replay loop (phantom level-2 advancement on multi-tier flows).

## Decision

**The graph stays the editing truth; advanced semantics ride three channels — approver_map object markers (runtime-resolved assignees), graph-owned extras keys (sign_modes / cc_after / condition_dsl), and the transition rows themselves (rejectTo and the general condition's positive literal). act()'s approve/reject routing became row-driven (conditional rows first, unconditional fallback); the shared rules resolver demotes to the no-rows fallback. The effective hooks converge on effectiveEffects() as the single exit every entry calls.**

- **Marker assignees**: deptLeader / supervisorChain / formField compile to `{type, emptyPolicy, emptyAssignee?, levels?, value?}` objects inside approver_map; openTodo resolves them per document — the submitter's main-department (mainDepartmentId, first membership fallback) isOwner members, the owner chain up parentId for N levels, or the user the document's own field names (`row[field] ?? row[field+'_id']` — REST rows carry the raw FK column). Empty resolutions apply the node policy: transferAdmin/assignUser re-route the todo, autoPass/autoReject advance through act('(auto)') with a depth cap of 8 and '(auto)' audit rows. The existing department-wide OR form interops byte-for-byte with the new「部门成员」assigneeType (department entries no longer import as deptLeader).
- **Countersign / sequential**: extras.sign_modes records non-OR tiers per role; countersign opens every todo, any reject rejects the whole document, and only full approval advances (one from=to audit row per signature); sequential opens one todo at a time, out-of-turn actors are refused (no todo), and the next assignee's todo opens in resolution order.
- **rejectTo**: the approval node's rejectTo property compiles to the `pending_level2×reject→pending` row (no rejectTo keeps →rejected); a reject landing on a waiting state (any state with an approve-leaving row) re-opens that tier; the importer reads the row back as approval_2.rejectTo.
- **General conditions**: condition rows extend to multi-row (AND/OR) × eight operators (`> >= < <= == != contains in`); a single `field > number` row keeps the B1 threshold template (the mirror literal on the direct-approve row); richer shapes compile the v2 way — the positive literal rides the pending→pending_level2 row, the amount keys drop, and extras.condition_dsl='v2' marks the flow (nb_approve's row-driven detection). approval-rules' conditionApplies parses the same DSL (clause sequence + one joiner), shared by both entries.
- **cc runtime**: the compiler attaches cc nodes to their chain anchor's LEFT state (start→draft, approval_i→pending/pending_level2) into extras.cc_after; an approve transition leaving a keyed state fires read-only kind='cc' todos (wfl_approval_todos gains the kind column idempotently; NULL reads as todo; every aggregation count excludes cc).
- **Byte-neutral migration**: the compiler leaves default amount values implicit (no extras key when amount_field=total or the threshold is 100000) and the equivalence assertion normalizes through the engine's resolution lens (thresholdOf / the total default) — after the ten-type migration every extras is byte-identical to its seed shape (hub_po/so_orders/pur_payments/mfg gain nothing; pur_orders keeps its 200000), so the W2-B5「so_orders carries no amount_threshold」probe passes untouched. Single-approval publishes still carry the template's vestigial pending_level2 rows; the importer decides two-level-ness by whether the gm role is mapped, never producing an assignee-less level-2 node.
- **Three-entry convergence (BP-02/14)**: effectiveEffects(token, docType, docId, code) is the only exit for so_orders→reserveForSo and mps_plans→recalcPlan; CLI --act, HTTP /act (inline), and the new idempotent POST /effective-effects all call it; nb_approve detects advanced flows (object approver_map entries or sign_modes/cc_after/condition_dsl keys) and delegates whole to the engine's /act, while its local path reaches the same exit after an effective landing (unreachable engines fail loud with the replay path, never silent). The CLI's effect chain races a 25s timeout against transport hangs.
- **Page-callback loop cut**: engine-written audit rows over HTTP are source='engine' — the page-callback workflow replays /act for source='page' rows, and engine-written 'page' rows made every HTTP act replay once (phantom level-2 advancement on multi-tier runs); genuine page intent rows still trigger the callback and are consumed by the engine, provenance living on the intent row.
- **Decoration-title heal**: the flowModels w3b4edtnkmzmd50m JS block's promise text heals from「发布派生在 B1」to the current state (save-then-read-back verify, throwing on a silent no-op); --assert gains the negative check (no stale text remains).

## Pitfalls pinned

- **The page-callback workflow replays /act on source='page' rows**: the HTTP route's hardcoded 'page' source made the engine re-trigger its own acts (double act entries in the logs); engine-written rows must be 'engine' — 'page' belongs to page-created intent rows only.
- **Template vestigial rows**: single-approval publishes still emit the pending_level2×approve/reject rows; an importer that decides two-level-ness by row existence produces an assignee-less level-2 node and deadlocks the round-trip — decide by the gm role's mapping presence.
- **fields:list dual shapes**: REST field rows may serialize options as a JSON string and put the relation target on the top-level `target` column (not options.target/targetCollection) — both reads are needed (a single read rejected every formField gate and produced an object-set field vocabulary).
- **Defaults stay implicit**: writing default amount keys breaks the W2-B5「so_orders carries no amount_threshold」probe — the engine already resolves defaults, so byte-neutral migration keeps them implicit.
- **psql `-t -A` prints the command tag for `DELETE … RETURNING`, not the rows** — cleanup scripts SELECT ids first, then delete.
- **The CLI's effective-hook chain can hang on a dropped keep-alive socket** (unsettled top-level await, exit 0 with a warning) — race a timeout and complete through the idempotent /effective-effects replay (disclosed in evidence).
- **oxlint narrows JSON.stringify to `string`** (not `string | undefined`): `?? ''`, `=== undefined`, and `as string` each trip a different rule — convert unknown to text with `typeof x === 'string' ? x : JSON.stringify(x)`.

## Alternatives

- Pushing countersign aggregation into SQL (todo-table aggregate queries) — rejected: not portable across NocoIO (REST/in-memory); application-level aggregation inside act() trusts the existing rows.
- Compiling general conditions into multiple transition rows — rejected: combinatorial explosion and the reject routing is inexpressible; one positive literal plus row-driven evaluation is the row table's minimal extension.
- nb_approve reimplementing every advanced semantic locally — rejected: dual implementations drift; delegation gives each feature one code path, and the local twin keeps only the static template (byte-equal to the existing path).
- Relaxing the W2-B5 probe to accept explicit default keys — rejected: the migration should converge onto the status quo, not demand the status quo relax; implicit defaults pass the probe unchanged.
