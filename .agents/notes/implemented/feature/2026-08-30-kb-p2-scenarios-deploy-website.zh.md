# Agent Note：P2 场景集、私有化部署与官网对接

Status: implemented

[English](2026-08-30-kb-p2-scenarios-deploy-website.md) | 中文

## 问题

P2-2 把产品铺开：向计划 30 个场景对齐的场景框架、不引入新基础设施的单租户私有化部署指南、ftd.lzqz.cn 形态运营站的对接（[`plans/food-kb-agent-plan.md`](../../../../plans/food-kb-agent-plan.md)，P2 §2/§4/§5）。

## 决策

- **场景是目录契约，不是代码**：`preset.yml`（展示元数据 + 保证能被语料命中的 `probe` 查询）+ `agent.cordis.yml`（与 shipped 预设相同的薄 persona + scoped tool-kb 形态）+ `SKILL.md`（何时检索、引用格式、何时用图谱工具）+ `data/corpus.md`（脱敏场景语料）。加场景是纯内容操作：复制目录、改写四个文件——场景集快照（`tests/scenarios.spec.ts`）自动纳入（结构、真实 Loader 挂载、检索专用工具面、自有语料的带引用检索）。
- **首发 11 个场景，覆盖全部 8 个类别**（会议纪要五类需求 + 研究报告的出海/设备/数据资产类）；向 30 对齐的其余 19 个在 `scenarios/README.md` 点名为纯内容填充。一个快照覆盖全集——逐场景快照文件会重蹈计划自己的成本警告（风险 #7）。
- **部署不新增基础设施**（`DEPLOY.md`）：systemd 单元、一个 SQLite 文件（WAL 备份说明）、仅含 MiniMax key 的 `.env`、`DSH_HOME` 重定向、升级时 fail-loud 的 schema 所有权。一个部署 = 一个租户；检索专用工具禁用作为组合事实写明，评审在 patch 里看得见。
- **官网对接是映射文档，不是 API**（`WEBSITE.md`）：计划 P2 §5 原文把运营站定为经 dsh SDK（JSON-RPC/ACP）驱动 harness 的独立前端——交付物因此把站点能力（注册/订阅/积分/存储钩子/引用溯源）逐一映射到既有仓库落点（租户绑定、预设、`ctx.kb.usage`、工作台面板、编号引用），并点名 SDK 是唯一契约。未为它新增私有端点。

## 备选方案

- **场景生成脚本**——否决：每场景四个小文件比生成产物更易评审；快照才是不变量。
- **部署指南引入 Docker**——否决：计划的约束是不引入新基础设施；systemd + Node 覆盖单租户场景。运维要用 Docker 不需要我们在此背书。
- **为官网做只读 BFF 端点**——否决：计划条目点名 SDK 为通道；网关 `kb.*` 域已服务认证客户端，CORS 全开的 stats 端点是无映射能力的新攻击面。

## 后果

- 场景集快照是未来每个场景免费继承的门；两个 shipped 角色预设兼作场景（列入 README 填充清单）。
- 部署、备份、升级行为集中在一页双语指南，现场工程师可照抄执行。
- 官网映射给业务侧一个稳定故事（免费层 → 角色订阅 → 数据资产服务），每个主张都指向已交付机制。
- 已知缺口：30 个场景中 19 个仍是内容填充；框架与快照是让它们变便宜的交付物。
