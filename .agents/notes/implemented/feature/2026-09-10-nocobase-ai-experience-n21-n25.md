# Agent Note: NocoBase AI experience N21–N25 — attachment proxy, native images, portal AI employees, think filtering

Status: implemented

English | [中文](2026-09-10-nocobase-ai-experience-n21-n25.zh.md)

## Problem

Three user-facing asks on the frozen NocoBase 2.2.6 OSS snapshot: attachments (pdf/docx/xlsx/md) uploaded into AI-employee chats were invisible to the model, image visibility was unverified, and the portals' "AI 智能填表" entry was dead (its hardcoded `form-assistant` employee never existed and its one-shot 45s completion timeout cannot survive MiniMax-M3's 15–100s reasoning). A fourth irritant: M3 answers arrive with an inline `<think>…</think>` reasoning chain that end users see. The snapshot cannot be modified, so every fix has to land in runtime configuration, REST, vendored portal sources, or a local proxy.

## Alternatives considered

- Frontend-side parse-and-inject before upload (Portal or admin components) — rejected: covers only the touched entry points; the floating ball, workbench, admin popups, and workflow LLM nodes all bypass it, and parsed text pollutes conversation history as ordinary messages.
- Modify the snapshot provider's attachment routing — rejected outright: violates the frozen-snapshot constraint.
- Seed the missing `form_assistant` employee to revive AiFillPanel — rejected: the user asked to replace the panel, not rescue it; the one-shot timeout remains structurally incompatible with M3 latency even with a live employee.
- Prompt-level "do not show reasoning" on the nine employees — rejected as the primary fix: M3 emits the think chain regardless; suppression is advisory while wire-level stripping is deterministic. It also touches nine prompt rows that then need bilingual maintenance.
- OCR or a vision-model route for images — rejected before any code: MiniMax-M3 natively consumes `image_url` parts (data URIs verified against the production API), and plugin-ai already emits exactly that shape.

## Decision

1. **Probe before building (N21).** A self-cleaning REST probe (`examples/kb-agent/scripts/nocobase-n21-attachment-probe.mts`) measures per-format visibility through the real wire (`aiFiles:create` + `aiConversations:sendMessages` with `attachments`), with a unique marker string per file, marker transcription as the verdict, conversation/file destruction in `finally`, and zero-residue assertions at both boundaries. Because NocoBase never logs the outbound LLM body, wire evidence anchors on the inbound request log (mimetype/extname select the parse branch) plus a direct-to-MiniMax differential proving the OpenAI `file` part is silently ignored while `<parsed_document>` text is consumed. The matrix flipped one assumption: pdf was the only truly invisible format; docx/xlsx/md/png were already model-visible.
2. **A loopback proxy is the single injection channel (N22).** The llmService "MiniMax" baseURL points at `http://127.0.0.1:13100/v1` (`examples/kb-agent/scripts/nocobase-n22-llm-proxy.mts`), which rewrites exactly the OpenAI file part — base64-decode, extract the PDF text layer through unpdf (same channel as `packages/kb/tool-kb` `extractPdfText`, zero new dependencies), replace with a `{type:'text'}` part in the same `<parsed_document filename="…">` envelope the upstream document-loader injects for docx/xlsx/md. This covers every consumer of the llmService (employee chat, workflow LLM nodes, `ai:listModels`). The whitelist risk was resolved by reading the snapshot: `checkUrlAgainstWhitelist` only enforces when `SERVER_REQUEST_WHITELIST` is set; unset (this repo's launch path) it warns and passes, so the loopback baseURL needs no configuration. Rollback is one command (`ai-proxy stop` auto-rewrites the baseURL to direct; `ai-direct` does it alone). Parse failures, non-PDF file-part MIMEs, and text-layer-free PDFs fail loud with named-file HTTP errors — a silently ignored attachment is the exact failure mode the proxy exists to remove.
3. **Images ship with zero harness changes (N21/N23).** M3 consumes plugin-ai's existing `image_url` data-URI parts natively; the boundary probe pinned single-image ≤10MB (JPEG/PNG/GIF/WEBP) with oversized uploads failing explicitly in the client rather than silently. No OCR, no vision routing, no re-encoding.
4. **Portal form entry is an avatar button plus embedded chat (N24).** All four mounts (CRM deals/leads, Hub expenses/sales-leads) replace AiFillPanel with `useAiEmployeeFill` over vendored components only: dex avatar beside the drawer footer buttons, ChatInline panel inside the form, form-registry + frontend-tool-registry declarations following the existing `ai-form.tsx` pattern. Streaming output dissolves the fill-without-feedback debt by construction. Two upstream behaviors are neutralized at the mount, not in vendored shared code: a `FormFillerAutoApprover` component approves this panel's formFiller interrupts (the vendored provider hardcodes `canAutoApproveToolCall` false while the server marks formFiller auto and waits — without the approver the tool card deadlocks in "running"), and an `openingRef` guard debounces double-clicks so one panel and one session open.
5. **Think chains are stripped on the response wire (N25).** A captured stream proves M3 emits reasoning inline in `choices[].delta.content` (no separate reasoning field exists on this wire), opening and closing tags sharing frames with answer text. The proxy therefore runs one `ThinkFilter` state machine per choice per stream: partial tag prefixes split across chunks are held back (≤6 chars) until completed or disproved, the finish frame absorbs held text outside think (content-before-stop ordering), SSE frames are re-decoded through a StringDecoder and re-emitted byte-identical unless their content changed, and unparseable frames pass verbatim. Non-streamed bodies filter `choices[].message.content` through the same machine; any shape surprise returns original bytes. The switch is `N22_FILTER_THINK` (default on; `0/false/off` restores verbatim pass-through after a proxy restart — the rollback path lives in the proxy header comment and QUICKSTART.zh.md). Per-stream logs carry segment/char/frame counts, never reply text. `examples/kb-agent/tests/n22-think-filter.spec.ts` pins the machine keylessly (13 cases, including chunk sizes 1–40 through both tags and the mid-delta tag that real traffic never split).
6. **Orphan n18 buttons self-heal, and verify counts by owned prefix (N25/N26).** `flowModels:destroy` cascades to a form's children, but `flowModels:save` accepts a dangling `parentId` — both facts established by live probe — so orphans can persist from replay/uid drift. `nocobase-n18-form-ai.mts` destroys any `n18ai-` button whose form uid matches no CreateFormModel row and says so; a second run reports none left. `setup-nocobase.mts verify` counts AIEmployeeButtonModel rows by the `n18ai-` prefix (≥8, and every such row prefixed) so foreign buttons can neither pad the count nor hide among ours.

## Consequences

The proxy is a single point of failure for every AI surface, paid back deliberately: `/healthz` and the baseURL wiring are verify assertions with the fix command in the failure text, and `ai-proxy stop` rewrites the llmService back to direct upstream so the surface degrades to the pre-proxy state (PDF-only loss) instead of a dead endpoint. Attachment visibility, portal replacement, and think filtering are pinned by evidence docs under `examples/kb-agent/demos/nocobase-full-features/` (`N21-attachment-visibility*.md`, `N22-attachment-proxy.md`, `N23-image-boundary.md`, `N24-portal-ai-employee.md`, `N25-think-filter-and-selfheal.md`) plus the keyless filter spec; the operator guide for attachments, portal mounts, boundaries, and switch rollback lives in `examples/kb-agent/QUICKSTART.zh.md`. Known gaps stay visible: Hub form mounts fill fine but their target collections do not exist in this instance (submit fails explicitly), M3 fill latency varies 40–240s (streaming keeps feedback alive), and image-only PDFs have no text layer to extract (the proxy rejects them by name).
