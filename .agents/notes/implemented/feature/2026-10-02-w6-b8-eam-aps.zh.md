## Decision

### 1. EAM 域（四集合 + 预防性引擎 + 状态机 + Andon 打通）
- `eam_assets`（8 台速冻水饺产线设备：和馅/速冻/金检/包装/温度计/天平/pH + 报废态样例；`ccp_code` 列把金检机↔CCP-JC-01、速冻机/温度计↔CCP-SD-01、搅拌机↔CCP-XT-01 与 W6-B4 监控点同编号挂钩；`workcenter_id` 挂 FCS 工作中心——Andon 请求按工序工作中心自动关联设备）、`eam_maint_plans`（周/月周期 + 点检清单 + next_due_date）、`eam_maint_orders`（new→accepted→done→closed 四态单向 CAS；done 需维修说明；close 限发起人或 admin——计划 §5.6「申请者验收才 Close」）、`eam_calibrations`（强检四台：金检机过期 10 天 critical / pH 计 3 天 critical / 温度计 14 天 warning / 天平在期）。
- 预防性引擎 `scanMaintPlans`：到点计划按「每个错过的周期一张工单」（dedup_key=`plan:{id}:{due}`）补生成后把 next_due_date 按周期前推（补漏上限 24 个周期，坏周期跳过并留 error）。挂引擎小时级 alert-scan 同一 tick（未 seed 的库静默 no-op）+ `POST /eam/scan-plans` 手动触发。
- Andon 维护请求（B4 占位接活）：`cards.html` 齿轮菜单启用 → `POST /andon/maintenance`（cardFlowOperator 会话推导发起人 + 生产车间部门围栏）→ 按工序工作中心挂设备、关联设备态翻 `repair`、生成 P1 工单；断言实测全链（含 XSS 载荷入库原文 + 渲染面 esc 防线）。
- 围栏：维保处理（accept/done）限 生产车间/admin（无独立设备部——车间承担设备职能，错误文案写明「设备/生产/admin」）；关闭限发起人/admin；buyer 全链 403。

### 3. APS 增强（frePPLe 理念、无求解器）
- **瓶颈归因 + 负荷热力**（`/aps/load`，APS瓶颈与负荷页 JSBlock）：负荷率=Σ planned_min ÷（班次跨度×并行，`dailyCapacityMinutes` 与 FCS 同式）；瓶颈=负荷率>100% 且含开放工序的桶，逐行列占用 MO 归因；WC×14 日热力矩阵（绿<80/黄≥80/红≥100）。口径对账：手写 SQL 与引擎输出行数相等（断言实测 1=1，W2-B6 1200 分 > 480 分/日 = 250% 在列）。
- **what-if 沙箱**（`/aps/whatif`，纯内存）：仅重排 status='planned' 工序（started/done 为冻结底载），MO 序=（boost 优先, need_date, code），同 MO 工序链序、不跨天、周日+日历节假日休——FCS 语义原样；旋钮=每工作中心加班分钟/日（0-960 校验）+ MO 优先级。**零写入**（断言用 mfg_order_operations 全表 md5 前后一致实证）。
- **Promote**（`/aps/promote`，计划部（PMC）/admin 围栏）：同场景重算后逐行 `UPDATE … WHERE status='planned'` CAS 写 planned_date、刷新 MO planned_start/end，`aps_whatif_runs` 留参数+delta+applied 审计行（差异报告留存）。

### 4. 坑与修复（本批实测踩到）
- `-t -A` 下 `INSERT/UPDATE … RETURNING` 输出「行 + 命令标签」两行——`Number('5\nINSERT 0 1')=NaN`；取首行解析（promote run_id 与 /eam/act 返回码两处）。
- RunJS 校验器：声明前引用的 `render` 判「未知全局」（改为提升的 `function paint()`），`instanceof Element` 同罪（鸭子判定替代）。
- JSBlock 交互键序：runSim/promote 必须**先读旋钮再 paint**（paint 重建 DOM 会把输入重置回默认值——症状是场景永远空参数）。
- `mfg_holidays` 列名是 `calendar`/`date`（不是 calendar_id/holiday_date）。
- what-if 断言重跑容差：同场景首度 promote 后存储计划已在新日期，复跑 moved=0 属稳态——移动证据回落到首轮 run 行的 delta->moved（断言两路取据）。
- 观察到一次 b4-assert 正常报工腿瞬时 engine_error 后自愈（重跑 ALL PASS×2 + 同状态探针 200）——演练 MO 余量边界态，非本批代码回归；如实记录。
