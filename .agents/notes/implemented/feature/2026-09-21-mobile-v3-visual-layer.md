# Agent Note: mobile v3 visual layer — cold-chain ledger token tracks, phase stamp, markdown pipeline, and the `+` sheet

Status: implemented

English | [中文](2026-09-21-mobile-v3-visual-layer.zh.md)

## Problem

Batch 3a built the product-logic skeleton for the seven-kind message protocol (class structure, minimal styles), but the look was still the v2 WeChat-style navy track: `#192b4d` primary with gradient avatars and generic blue/orange/red semantics, 16px plain-text bubbles, a standalone contacts route occupying navigation, and KG evidence as an always-expanded card block eating the flow. The visual spec (plans/2026-09-21-mobile-v3-redesign/03-visual-design.md) set the direction as a cold-chain ledger: ink-teal/mist/frost brand axis, the 44px phase stamp as the single signature element, tabular digits with the monospace ticket face, light/dark as whole swapped tracks, and exactly three motions.

## Decision

**The two token tracks are the only skinning point.** [tokens.css](../../../../packages/client/ui-mobile/src/client/tokens.css) carries the full `--dshm-*` set from 03 §2.2/§2.3 (brand axis, three semantics, three temperature layers, bubbles, structure, font stacks); every `--adm-*` override became a var() reference, so the dark track only redefines `--dshm-*` and antd-mobile follows — v2's duplicated hardcoded dark `--adm-*` block is gone. The dark selected foreground rides `--dshm-on-primary` (white on light, teal-black on dark) per the §2.5 contrast verdict. The v2 `--dshm-info`/`--dshm-teal` tokens were deleted and their references migrated: badge.info folded into the primary look (the KG provenance lakehouse badge rides it too), task-cards' title icon switched to primary.

**The markdown pipeline justified its new dependency.** No PC-side package rendered markdown (only the isolated platform/nocobase subtree carries it), so ui-mobile adds markdown-it + DOMPurify (03 §4.5's chosen pair), with the pure pipeline in [rich.ts](../../../../packages/client/ui-mobile/src/client/messages/rich.ts): md with html:false/breaks:true (CJK single newlines stay line breaks), DOMPurify-sanitized output through dangerouslySetInnerHTML. Numeric conclusion lines promote to half-width metric pairs (≤16 chars, digit-leading or >60% density over non-whitespace, not a markdown structure line, splits into a non-empty label plus numeric value with unit words absorbed into the value); key-info highlighting does no lexical name detection — `strong` simply gains weight 600 plus the 2px primary-10 underline (bold syntax is the signal; no guessing entity names). The density denominator is non-whitespace characters: the spec's own example「本月采购额 ¥182,400」is 57% with the space and 61.5% without, so the whitespace-stripped reading is the one where rule and example agree.

**The phase stamp (the signature) owns four states and the one dramatic motion.** The [PhaseStamp](../../../../packages/client/ui-mobile/src/client/forms/v3/PhaseStamp.tsx) is a 44px round seal: draft hollow slate ring, pending primary ring with DotLoading inside, submitted solid pass-green (row number as a №/digits pair in the mono face), rejected brick ring with the 45° slash. The stamp lands with a 200ms cubic-bezier(0.2,1.4,0.4,1) animation and the card rim flashes green for 300ms via `.card:has(.stamp[data-phase='submitted'])`; all three motions (item entrance 180ms, pick feedback 120ms, the landing) each degrade explicitly under `prefers-reduced-motion: reduce`. The entrance rides a CSS animation on `.flow > *` — stable React keys do not replay it, only genuinely inserted nodes animate.

**The derived read-only expansion is the "changeable but never asked" surface.** DraftCard's derived fields rest as read-only rows (value plus the 「·依据」 annotation); tapping a row swaps in the override input, required fields stay ordinary controls, and edited fields carry the 3px ink bar with the primary-10 tint (the re-edit diff). The receipt card draws its own three-dot ticket trail (12px dots, 2px rim lines — antd-mobile Steps' numbered circles do not match the spec) and adds the 查看这条记录 secondary entry (onView sends the same read-back follow-up as the receipt-phase chip).

**IA convergence: the `+` sheet and the KG entry row.** [NewChatSheet](../../../../packages/client/ui-mobile/src/client/messages/NewChatSheet.tsx) (antd-mobile Popup) replaces the contacts route: fill assistant pinned first with ≤3 form chips plus the three most recent sessions; ContactsView and its route are deleted while `#/contacts` joins LEGACY_HEADS redirecting to chats (old deep links live); entries sit in both the chats header and the chat header. KG evidence collapses to one entry row (「依据 · 知识图谱 N 条」) with the card flow moved wholesale into the bottom sheet, whose header gained an explicit close button (the jsdom Popup mask needs a pointer-event sequence to fire onMaskClick; the button also serves reachability).

**The avatar system retired its gradients.** ColleagueVisual's from/to pair became a single stamp color (ink-teal/slate/teal-ink) and `colleagueGradient` renamed to `colleagueColor`; Avatar's prop renamed to background; AI avatars carry the 10px stroked round "AI" seal at the lower right (stamp language, replacing the sparkles). The login page moved to mist with the 96px stamp-form logo (the 表 seal inside the dashed AI ring), fixing the v2 leftover where the logged-out page rendered outside `.dshm-root` and thus outside the token set (App.tsx's login branch now wraps the theme container). Profile became the identity card, the two-column monthly ledger metrics (本月登记 counts receipt fences across this month's fill-assistant sessions from the durable log; 待审核 counts the local marks), and 48px settings rows.

## Alternatives considered

- **antd-mobile Steps vs the hand-drawn ticket trail**: Steps' numbered circles do not match 03 §4.4's 12px-dot spec; the receipt's 「●─●─●」 is ~20 lines of CSS keeping the signature consistent.
- **Lexical entity highlighting vs strong-semantic highlighting**: recognizing "form/supplier/amount" names needs a dictionary or NER, unreliable on mobile; 03 §4.5 already treats bold as the signal, and the CSS-only strong treatment is the same semantics with zero false positives.
- **Per-session history projection vs the roster-duty summary**: the list summary should read the last message per 03 §4.7, but one history RPC per session under a polling list is unacceptable; the roster summary stays and the projection is logged as a deviation (④ above).
- **Keeping v2 gradient avatars vs flat stamp colors**: gradients are the "AI-default amplifier" 03 §8.2 explicitly retired; the flat color keeps the Avatar component and every call site, swapping only the `background` value and prop name.
- **Duplicated dark `--adm-*` vs var() references**: v2 re-hardcoded the whole `--adm-*` set on the dark track; var() references let the dark track maintain exactly one `--dshm-*` table with antd-mobile following, deleting ~15 lines and removing two-track drift.

## Consequences

- antd-mobile Popup under jsdom's animationless environment: `destroyOnClose` removal depends on the animation finishing, so unit tests cannot assert DOM disappearance after close (the real-browser e2e asserts detached fine); a CSS module `class ?? ''` leaves an unreachable branch, so classNames handed to Popup use an `as string` assertion.
- TS 5.5 infers type predicates from plain boolean predicates: `segments.find(s => s.kind === 'text')` is already narrowed, so a following `line.kind === 'text'` reads as always-true to oxlint — that comparison is gone; polling state discriminates on `status === 'ready'` rather than `value !== undefined && error === undefined`, the oxlint-clean form.
- The refreshed e2e golden naturally carries the v3 surfaces: the strong split, the picked card's ✓ seal, the № stamp, 查看这条记录, the KG entry button; mobile-shell e2e moved to the v3 copy and sheet interaction (the sheet must close before tapping the TabBar — the mask intercepts pointers).
- Coverage notes: the Popup mask click goes through `.adm-mask-aria-button` (the aria button antd-mobile's Mask renders); the metric promotion's punctuation-density edge (`,,,,,,,` passes density but has no numeric token) got its own test.
- Known deviations (implemented at spec values and logged here): ① `--dshm-muted-foreground` on `--dshm-muted` (#5c716d/#e8efed) measures 4.46:1, just under 4.5, at muted-background secondary-text spots like the systemFold summary; ② the session summary still reads the roster description/duty — 03 §4.7's last-message projection (receipt → 已登记 №N) needs per-session history reads and stays open; ③ 03 §4.7's swipe-to-pin/delete has no backend RPC (session.pin/delete do not exist), so SwipeAction is not wired; ④ Profile's 待审核 uses the local pendingReview marks — only 本月登记 satisfies the cross-device derivation.
