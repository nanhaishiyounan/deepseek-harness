# W11 语音输入真机验证清单（OQ-2 · 结论由用户回填）

> 目的：headless/桌面环境的 green 不等于真机 green（B2.0-R1 调研结论：微信双端 webview 大概率走「不存在→语音格隐藏」分支）。本清单 5 分钟可完成；每格只需回答「通过 / 不通过 / 现象」。
>
> 前提：手机能打开部署地址。语音功能要求 **HTTPS**（`https://` 域名访问；局域网 `http://IP:3080` 下语音格预期**隐藏**——这本身就是一项要验证的降级）。

## A. 微信内（主战场）

| # | 步骤 | 预期 | 实测结论（回填） |
|---|---|---|---|
| A1 | 微信里打开任意聊天 → 把部署链接发给自己（或文件传输助手）→ 点开 | 页面正常加载，无白屏 | |
| A2 | 进入任一同事会话 → 点输入框左侧 **＋** | 面板展开；工具区**三格**（拍照/相册/文件），**无语音格** | |
| A3 | （若 A2 出现了语音格）点「语音」 | 不卡死、无白屏；不可用应弹「当前环境不支持语音，试试拍照或打字」 | |
| A4 | 点「拍照」拍一张单据照片 → 等待 chip 转好 → 发送提问 | 附件 chip 出现 → AI 回答引用图中内容 | |

## B. Safari 直开（iOS）

| # | 步骤 | 预期 | 实测结论（回填） |
|---|---|---|---|
| B1 | Safari 打开同一 HTTPS 地址 → 进入会话 → 点 **＋** | 工具区**四格**（含语音）；若只有三格，记录 iOS 版本 | |
| B2 | 点「语音」 | 弹麦克风授权 → 允许后出现柿橙脉冲聆听卡 | |

| B5 | 拒绝麦克风授权后再点「语音」 | Toast「麦克风权限被拒绝，请在系统设置中允许」，无卡死 | |

## D. 局域网 HTTP（降级验证）

| # | 步骤 | 预期 | 实测结论（回填） |
|---|---|---|---|
| D1 | 用 `http://IP:3080` 打开（任意浏览器）→ 点 **＋** | **三格**（无语音格）——secure context 门槛的正确降级 | |

## 排查提示

- **语音格不出现**＝当前环境无 SpeechRecognition（A2/D1 的预期行为，非 bug）。
- **语音格在但点击 Toast「不支持语音」**＝引擎存在但构造/启动失败（`broken` 态，同样预期内）。
- **聆听卡一直转、无文字**＝识别服务不可达（Chrome 的识别走 Google 服务，国内网络下常见）；等 6 秒应自动退出并 Toast，若卡死请记录机型+浏览器版本。
- 需要看日志时可在地址后拼 `#/login` 用同一账号重复操作，控制台（Safari「开发」菜单 / Chrome `chrome://inspect`）截图回传。
