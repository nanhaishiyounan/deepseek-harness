## 3. 启动与运行手册

完整手册 [`QUICKSTART.zh.md`](../examples/kb-agent/QUICKSTART.zh.md)；根 [README.zh.md](../README.zh.md) "本地启动"节为快速入口。

冷启动全链（从零到完整系统）：

```sh
pnpm install                                        # 仓库根；Node ^22.19 || >=24
node --import tsx/esm examples/kb-agent/scripts/setup-nocobase.mts   # 默认 all，见下
DSH_HOME=examples/kb-agent/.dsh pnpm dsh web --patch examples/kb-agent/cordis.patch.yml --no-open
node --env-file=.env --import tsx/esm examples/kb-agent/scripts/kg-build.mts
```

`all` 链内部顺序（[`setup-nocobase.mts:706-728`](../examples/kb-agent/scripts/setup-nocobase.mts:706)）：install → build（首次 `yarn build` 约 23 分钟，产物就位后秒级）→ start → init（五 collections + 种子 + workflow + 凭据写 `.env`）→ plugins（13 个功能插件）→ ai（llmService）→ 依次子进程重放 crm-modules → hub-modules → n13-rebuild → n13-seed → n14-fix → n17-alignment → n18-form-ai → verify（全部断言组）。

日常启停：PG17 `pg_ctl -D /usr/local/var/postgresql@17 start`（`pg_isready -h localhost -p 5432` 探测）；NocoBase `setup-nocobase.mts start` / `verify`（verify 带 `--env-file=.env`）/ `stop`；DSH Web 即上文 `dsh web` 命令。

reset 后单跑 `all` 即得完整系统（N16 幂等语义）：`setup-nocobase.mts reset`（drop 库重装）后单跑 `all`，七个重放脚本全部幂等（二跑 kept / +0），无需任何手动步骤；portal 产物由 verify 探测兜底（构建走独立 [`nocobase-portal-deploy.mts`](../examples/kb-agent/scripts/nocobase-portal-deploy.mts)）。

账号与凭据：根 `.env` 持 `MINIMAX_API_KEY`（对话/嵌入共用）、`NOCOBASE_BASE_URL` / `NOCOBASE_API_KEY`（init 自动写入）——**不提交**；NocoBase 初始账号 `admin@nocobase.com` / `admin123`。

BUG-4 重启契约：服务端源码改动（`packages/**/src`）后需重启 `dsh web` 进程；客户端改动需 `pnpm run build:lib:client && pnpm run build:web` 后重启。

外网代理（clone / 访问 GitHub 等操作前导出）：`export http_proxy=socks5://127.0.0.1:1087 https_proxy=http://127.0.0.1:1087 ALL_PROXY=socks5://127.0.0.1:1080`；MiniMax 端点可直连无需代理。

分级列出；每项给定位与建议修复路径。"上游"指 NocoBase 2.2.6 快照或其商业版，按约定不修改 platform 快照。

**上游 / 商业（等价实现已做）**

- multi-portal 与 AI-mode 独立前端为 v12 商业能力（`plugin-multi-portal` 不在 OSS preset，multiPortals API 404 双证据）；等价实现为 admin 应用中心页。建议：等官方 OSS 化或采购，暂用应用中心。定位 [B「N17」诊断 2](nocobase-full-features/01-batches.md)。
- plugin-ai 上游 `Sender.tsx` 双击发送会开 2× 会话窗口（N18 会话验证发现，上游组件行为）。建议：改上游成本高，优先在挂载侧做按钮 busy 守卫防抖；或随快照升级观察上游修复。
- llmService apiKey 以明文存 NocoBase DB（`llmServices` 表 options.apiKey）；本地演示可接受，生产前应接密钥管理。定位 [`setup-nocobase.mts`](../examples/kb-agent/scripts/setup-nocobase.mts) `ensureLlmService`。
- AI 悬浮球 / 聊天面板会把模型推理文本（MiniMax-M3 `<think>` 链）回显给最终用户（N18 会话验证发现）。建议：前端渲染层过滤 think 段，或 prompt 侧抑制。

**体验债（不阻断功能）**

- 表单 AI 填充端到端延迟 15~100+s（MiniMax-M3 推理后才调 formFiller 工具，非网络问题；n18-capture 按 150s 等待窗口）。建议：做流式反馈（面板内逐字输出 + "正在填写…"状态），或对明确槽位类意图走直填分流不经 LLM。定位 [B「N18」备注](nocobase-full-features/01-batches.md)。
- `n18ai-` 按钮 dirty 删除自愈弱：表单节点被删后重建，确定性 uid 会重建按钮，但"按钮挂在已废弃表单 uid 上"的孤儿场景未覆盖（N18 会话验证发现）。建议：n18 脚本对 formUid 做存在性校验后 upsert。
- v2 Add new 表单空值可提交（字段无必填约束，空表单落库空行）。建议：FormItemModel wire 或 collection 层加必填约束。
- AI 头像按钮无 a11y 可访问名（40px 图标按钮，屏幕阅读器读不出）。建议：挂载时补 aria-label（需上游 props 或本地 patch）。

## 9. 接手建议（按优先级）

1. **浏览器复验 N18 表单 AI**（半小时）：按第 3 节拉起双入口 → :13000 任一 v2 表格页（如客户）→ Add new → 弹窗右下角 Dex 头像 → 输入中文意图（例："漯河一家中型调味品企业，名叫XX食品"）→ **耐心等 15~100s**（MiniMax-M3 推理后调 formFiller）→ 检查六字段中文填充 → 提交落库 → NocoBase 表格核对新行。证据形态对齐 `demos/nocobase-full-features/N18-*.png`。
2. **双击防抖**（上游 Sender.tsx 或挂载侧按钮 busy 守卫）：消除双击开 2× 会话窗口；改动最小面在挂载侧（n18/n17 wire 或本地覆盖组件），修上游需评估快照同步成本。
3. **填充流式反馈**：面板内逐字输出 + "正在填写…"状态（体验债第一项）；若接受产品简化，可对槽位明确的意图走直填分流。
4. **提交切分**：工作区大量未提交改动（09-08 起叠加）。建议分组边界：① 平台修复面（ui-kg/launcher/setup——D 批次一/二）；② NocoBase 脚本与 verify 断言（`examples/kb-agent/scripts/`）；③ 文档与计划（plans/、QUICKSTART、README）；④ 截图与 demo 产物（demos/，确认 pairing manifest 排除生效）；⑤ portal vendored 目录（先向用户确认提交/忽略决策）。提交前跑 [dsh-pre-push-checks](../.agents/skills/dsh-pre-push-checks/SKILL.md) 选最小覆盖面。
