## 1. Aesthetic Direction

**方向陈述：冷链票据台账——把"登记一条单据"做成一张冷色调的电子三联单：AI 负责誊写，人负责盖章，落库即生效。**

为什么适合食品行业企业供应链（而不是微信复刻或 SaaS 后台脸）：食品供应链移动场景的本质是**单据流转**——采购、入库、质检、回款，从业者一天的信任模型是"白纸黑字、盖章生效"，不是"聊天社交"；消费聊天 app 的暖社交感（微信绿、多彩渐变头像）会稀释单据的严肃性，而 SaaS 后台脸（蓝紫渐变、浮起白卡、无限阴影）没有行业记忆点。冷色调（墨青、冷雾白、青灰）来自冷链与品控的行业视觉——HACCP 青蓝、冷库雾白、检验单油墨；票据感来自结构：分区字段行、tabular 数字、编号大数、相位戳。用户在手机上做的不是"和朋友聊天"，而是"把嘴里的一句话变成一张可盖章的票"。

**Signature element（唯一记忆点）：相位戳（Phase Stamp）**——每张表单卡右上角一枚圆形戳记，随生命周期翻转：draft=空心灰环「待确认」、pending=青色描边「提交中」、submitted=检验绿实心「已登记」+行号、rejected=砖红斜杠「已驳回」。提交成功时戳记以 200ms"盖章"动效落下（全应用唯一戏剧性动效，§6）。它编码的是真实信息（卡片相位，01 ②f-1 结构化动作的可视化），不是装饰；它是"人审=盖章、落库=生效"这一行业心智在整个界面里的唯一放声处。头像、徽标、空态图形全部借用戳记语言（描边圆章），使 signature 成为体系而非孤岛。

三大 AI 默认脸回避声明：①不是奶油底+衬线+terracotta——底色是冷雾白（青灰调），正文字体是系统黑体栈，暖色只出现在语义位（琥珀/砖红）；②不是近黑底+荧光绿——暗色模式是青黑（带绿的深灰阶），强调色是低饱和墨青；③不是报纸发丝线+零圆角——卡片 16px 圆角、气泡 18px 圆角，结构线是卡片内部分区线（票据的"栏"），不是全页 hairline 网格。

## 2. 色彩系统

### 2.1 主轴色（6 个命名 hex）

| 名称 | hex（亮色） | 语义用途 |
|---|---|---|

### 2.5 对比度校验（WCAG 相对亮度公式核算）

| 前景/背景 | 对比度 | 判定 |
|---|---|---|
| 青墨 `#1C2B29` / 冷雾白 `#F4F7F6` | 13.0:1 | 正文 AAA |
| 青灰 `#5C716D` / 冷雾白 `#F4F7F6` | 4.8:1 | 次要文字 AA（≥4.5 达标） |
| 白 / 墨青 `#0B5D56`（用户气泡） | 7.7:1 | AA |
| 检验绿 `#1F7A4D` / 霜白 `#FFFFFF` | 5.3:1 | 戳记文字 AA |
| 临期琥珀 `#A85A10` / 霜白 | 5.1:1 | AA |
| 驳回砖红 `#C0452E` / 霜白 | 5.1:1 | AA |
| 暗色：`#E4EBE9` / 卡 `#172220` | 12.6:1 | AAA |
| 暗色：`#9BB0AB` / 卡 `#172220` | 7.2:1 | AAA |
| 暗色：白 / 主色 `#4CA79C`（选中态） | 2.6:1 | 大字/图形级；选中卡文字改用 `#0D1413` 底色文字方案（`#4CA79C` 底 + `#0D1413` 字 = 5.9:1，AA） |

暗色选中态规则由此定死：**深色模式下 selected 用亮主色底 + 青黑字**（不是白字），亮色模式用主色底 + 白字——两种模式都落在 AA。工程实现按 `data-theme` 切换 selected 前景 token（`--dshm-on-primary`：亮色 `#FFFFFF`、暗色 `#0D1413`）。

## 3. 字体层级

**中文字体栈裁决**：`-apple-system` 打头（iOS 走 SF+PingFang 系统级渲染，零加载延迟），安卓回退 HarmonyOS Sans SC / MiSans（华为小米原厂字体，笔画现代、数字默认近等宽），再回退 Noto Sans SC / Microsoft YaHei。不用 webfont：中文字库体积（MB 级）换不来足够的品牌差异化，反而引入加载闪变；v2 把 Noto Sans SC 放首位的做法在低端安卓上有明显字体跳变，降级处理。**数字票据感**：全应用数字启用 `font-variant-numeric: tabular-nums`；回执行号（№ 1042）、单号（PO-2026-0042）、金额（¥16,000）三类"票号"额外用 `--dshm-font-num` 等宽栈——冷库温度记录仪的读数感。

| 角色 | 字号/行高 | 字重 | 字体栈 | 用途 |
|---|---|---|---|---|
| 显示标题 | 28/34 | 700 | sans | 欢迎屏问候语 |
| 指标大数 | 28/34 | 600 | num（等宽） | 回执卡行号、金额大数 |
| 页面标题 | 17/24 | 600 | sans | 导航栏标题、Profile 区块标题 |
| 卡片标题 | 16/24 | 600 | sans | 草稿卡/回执卡标题、弹层标题 |
| 气泡正文 | 15/24 | 400 | sans | AI/用户气泡、欢迎能力清单 |
| 字段值 | 14/22 | 500 | sans（数字 tabular） | 卡片字段值、列表摘要主体 |
| 辅助说明 | 13/20 | 400 | sans | hint、依据标注、选项摘要 |
| 字段标签 | 12/18 | 500 | sans | 卡片字段标签、chips 文字 |
| 时间戳/徽标 | 11/16 | 400 | sans | 时间、相位戳文字、未读角标 |

层级裁决：气泡正文从 v2 的 14 提到 15——聊天流是唯一正文层，15px 在 390 视口是单手可读下限；卡片字段值 14 与气泡拉开一档，让"卡"与"话"有密度差。

## 4. 组件规格

以下所有组件宽度的前提：聊天内容列左右各 12px 页边距；AI 侧内容 = 头像 32 + 间距 8 + 内容；气泡最大宽度 296px（AI 与用户同），卡片（任务卡/回执卡/欢迎卡）占满内容列全宽 = 390 − 24 − 40（AI 侧）= 326px。

### 4.1 聊天气泡（AI / 用户 / 欢迎语卡）

```

│ (32)                    │              │  好的，登记一张采购单。  │

  (6)                      │              其余角 18px
```

- AI 气泡：`--dshm-bubble-ai-bg` 底、`--dshm-bubble-ai-border` 1px 边、圆角 `18px 18px 18px 6px`、内边距 12px 14px、正文 15/24 青墨、`--dshm-shadow-card` 极轻影。头部无名称行（头像即身份）；AI 消息带 4px「AI」描边圆章徽标于头像右下角（stroke 圆 + 10px 字）。
- 回合级头像（裁决）：同一 AI 回合被 fold 拆出的连续消息段（气泡/卡/询问/回执，含中间的工具行）只在首段渲染头像与徽标，后续段渲染等宽（32px）占位列保持左对齐——微信范式：连续同人消息不重复身份。
- 用户气泡：`--dshm-bubble-user-bg` 底、白字（暗色按 §2.3）、圆角 `18px 18px 6px 18px`、内边距 12px 14px。
- 欢迎语卡（WelcomeCard，替代首条气泡的强化形态）：全宽 326px 卡、圆角 16、霜白底冷缘边；内部三段：问候（显示标题 28/700 青墨）→ 能力清单（气泡正文 15，每条前置 4px 墨青方点）→ 起点 chips 三枚（`--dshm-primary-soft` 底、字段标签 12 字号、全圆角、高 32）。卡与能力对应 02 §5.1 welcome 元数据。
- 选择回执胶囊（§2.5 已答态的 user 侧形态）：高 28px 胶囊、`--dshm-primary-10` 底、墨青字、字段标签字号、前置对勾图标；不渲染为大气泡。

```
│ ┌───────────────┐ │           │ (宏发食品·郑州)   │        │ [合格] [不合格]   │
│ │◉ 采购单        │ │           │ (宏发食品·漯河)   │        │ [让步接收]        │
│ │  向供应商买进   │ │           │ (宏发冷链·郑州)   │        │                  │
│ ├───────────────┤ │           │ [自己打字说明]    │        │                  │
```

- 问题文本：气泡正文 15/24 青墨，下距 10。
- 选择卡：全宽、高自适应（标题 14/500 + hint 13/20 青灰）、内边距 12 14、圆角 10、冷缘边；选中态整卡墨青底白字（暗色：亮主色底青黑字，§2.5）；已答态整组 opacity 0.55 + 所选项左上 12px 检验绿对勾章。

- free-text 入口：问题下方 13 青灰下划线文字「自己打字说明」，点击聚焦输入框。

### 4.5 AI 回答富渲染规则

- **Markdown**：气泡正文按 Markdown 渲染（选型 markdown-it + DOMPurify 消毒，移动端安全渲染；v2 纯文本直出的解）。加粗=同字号 600；列表=左 4px 墨青方点 + 4px 缩进；表格=两列表格化（label 列青灰 13、值列青墨 14/500，行高 32，表头行 `--dshm-muted` 底），超过两列的表格横向滚动。

- **关键信息高亮**：单据名、供应商名、金额在叙述中以 `font-weight:600 + 底部 2px --dshm-primary-10 下划线`呈现（不换色，保持冷色纪律）。
- **协议隐形**：`dsh` 围栏、表名、snake_case 字段名永不渲染（02 §2.4 折叠规则；01 ⑤C2/C4）。

## 5. 暗色模式

映射规则：亮暗两轨 token 同名整轨替换（§2.2/§2.3），组件零硬编码色值；语义色在暗轨统一提亮 1-2 档并降低 10% 底透明度饱和度（已落值）；温层色暗轨全部提亮至浅色位；**selected 前景按 `--dshm-on-primary` 切换**（亮 `#FFFFFF` / 暗 `#0D1413`，§2.5 对比度裁决）；阴影从"提层次"改为"沉边缘"（暗轨阴影加深但不加发光）。对比度校验：正文 ≥4.5:1（核算值 12.6:1）、次要文字 ≥4.5:1（7.2:1）、语义色文字 ≥4.5:1（success 4.6:1、warning 4.9:1、destructive 4.8:1 on 暗卡），全表见 §2.5。

## 6. 动效（克制原则：全应用三处，只服务信息变化）

1. **新消息入场**：聊天流新 item `translateY(8px)→0` + `opacity 0→1`，180ms `ease-out`——让"AI 在说话"有物理感，不弹跳。
2. **选项点选反馈**：点中选项 120ms 背景填充过渡 + 已答态整组 200ms 降不透明度——作答被界面确认（01 ④d"点选后选项组置灰"）。
3. **相位戳盖章**（signature 动效）：草稿卡翻 submitted 时戳记 `scale 1.25→1` + `rotate -8°→-3°` 落下，200ms `cubic-bezier(0.2, 1.4, 0.4, 1)`，同时卡片边框闪 300ms 检验绿——"落库即生效"的唯一放声处。

其余一律无动效（含暗色切换、弹层用 antd-mobile 默认）。三处动效全部 respect `prefers-reduced-motion: reduce`——退化为瞬时显示（无位移、无缩放、无旋转），信息不损失。

## 7. antd-mobile v5 边界

| 用 antd-mobile | 自绘 | 理由 |
|---|---|---|
| Popup（`+` 弹层、KG 证据弹层） | 聊天气泡（AI/用户/欢迎卡） | 气泡是品牌核心面，需完全控制圆角/边框/徽标 |
| Toast（写入失败、复制成功） | ask_choice 三形态选择组 | 交互语义全新（已答态重放派生），无对应组件 |
| Dialog（清空会话等破坏性确认） | DraftCard / ReceiptCard / 相位戳 | signature 元素与三分层布局，产品独有 |
| SwipeAction（会话列表滑动） | ActionBadge（动作徽标行） | 消息流内轻量元素 |
| PullToRefresh（历史加载） | 上下文 chips | 状态机阶段驱动，逻辑特殊 |
| TextArea + 发送钮容器 | KG 单行入口 | 简单行 |
| Picker / DatePicker / Stepper（字段控件） | 欢迎屏、登录页品牌区 | 品牌面 |
| Input / Checkbox（登录、多选） | Markdown 富渲染（markdown-it + DOMPurify） | 内容分级核心，需配合围栏剥离 |
| DotLoading（pending/running 态） | 指标卡 | 票据排版独有 |
| ImageViewer / Empty（兜底） | 会话列表项（徽标/摘要投影） | 摘要是 fold 投影，非纯展示 |

主题覆盖：`--adm-color-primary` 等全部映射到 `--dshm-*` 同名语义位（`--adm-color-primary: var(--dshm-primary)` 等，与 §2.2 同容器级联）；`--adm-border-radius-m/l` 对齐 10/16；`--adm-font-family: var(--dshm-font-sans)`。antd-mobile 组件因此自动随亮暗轨切换，无需单独适配。

## 8. 自评记录（frontend-design 两遍循环，方法论要求入档）

### 8.1 第一遍 brainstorm（默认答案清单，即"任何类似需求都会产出"的版本）

按 skill 要求先跑一遍"通用 AI 助手聊天 app"的第一反应：微信绿或品牌藏蓝主色；渐变圆头像（AI 蓝紫渐变）+ sparkles 图标；白底 + 浮起白卡 + `shadow-md`；AI 发现卡用渐变强调（直接沿用 FoodOperation teardown §6 的渐变发现卡）；气泡纯文本 + 代码块直出；或另一个极端——米白纸感 + 衬线标题 + terracotta 强调的"杂志脸"。

### 8.2 逐项自评与修订

1. **"品牌藏蓝 #192b4d 继承 v2"→ 修订为墨青 #0B5D56**：藏蓝是 v2 被判"丑"的现状，也是 SaaS 后台默认脸的近亲；换轨到墨青——冷链/品控行业色（HACCP 青蓝的油墨版），与微信绿、企业蓝紫、teal 消费 app 都拉开距离。改的是"默认信任 蓝=企业感"这一惰性。
2. **"渐变头像 + 渐变发现卡"→ 修订为单色戳记头像 + 相位戳**：渐变双件套是 FoodOperation 原型的脸（teardown §6 实测渐变卡 + 渐变头像），照抄即复刻而非超越；且渐变是"AI 默认感"的放大器。戳记把品牌押在**信息编码**（相位）上而非装饰上——skill 的"structure is information"原则的直接应用。
3. **"白底浮起卡 + 阴影分层"→ 修订为冷雾白底 + 嵌平卡 + 票据内部分区线**：浮起卡是聊天 app + SaaS 的双重默认；票据感来自卡片**内部**的结构（分区线、字段行、tabular 数字），外部只有 1px 冷缘 + 极轻影。这同时回应了 01 ②c：卡的可信感来自"像一张填好的单"，不是"像一块悬浮的玻璃"。
4. **"米白纸感 + 衬线 + terracotta"→ 整个方向否决**：撞 AI 默认脸①；且中文移动端衬线（宋体系）小字号渲染差，票据世界的中文原型（三联单/出库单）本来就是黑体+油墨，不是书卷。
5. **"欢迎屏放插画 + 产品 slogan"→ 修订为戳形 logo + 能力清单卡**：空态是行动邀请（skill: an empty screen is an invitation to act），插画是装饰噪音；能力清单直接回答"我能替你登记什么"（01 ④a 能力提示）。
6. **"数字用 SF Mono 全局等宽"→ 收敛为三处票号场景**：全局等宽破坏中文混排节奏；只在行号/单号/金额三处给票据读数感——克制的 signature 语言。

### 8.3 第二遍校验（对三大默认脸 + brief 逐条）

冷雾白底不是奶油 `#F4F1EA`（青灰调非暖调）；暗色是青黑非纯近黑、强调是低饱和墨青非荧光绿；16/18px 大圆角 + 卡内分区线，不是零圆角 hairline 报纸网格。Brief 逐条：超越微信范式点见 §9；富渲染（01 ④c）落在 §4.5；结构化消息组件落在 §4.2-4.4；"不是 SaaS 后台脸"落在色彩轨与卡片语言。校验通过，规格定稿。

## 9. 与 v2 的三大视觉差异（验收对照）

1. **色彩轨整体换血**：藏蓝 SaaS 轨（`#192b4d` + 通用蓝/橙/红语义 + 渐变头像）→ 墨青冷链票据轨（`#0B5D56` + 检验绿/临期琥珀/驳回砖红 + 单色戳记语言 + 温层行业色彩蛋）；亮暗两套 token 整轨替换，无一处沿用 v2 色值。
2. **卡片范式从"浮起白卡平铺字段"→"分区台账卡 + 相位戳"**：v2 全量平铺可编辑控件（[task-cards.tsx:43-46](../../../packages/client/ui-mobile/src/client/forms/task-cards.tsx)）换成三分层分区（需要你定/请确认·依据/系统生成折叠），卡片生命周期由 44px 相位戳一望即知，回执从裸 JSON `<pre>` 变成金额大数 + 行号戳的指标卡。
3. **聊天流从纯文本投影 → 结构化票据组件 + tabular 数字**：气泡接 Markdown 富渲染与指标卡化，协议负载（围栏/表名/字段名）在视觉层彻底隐形，选择/草稿/回执都是专用组件而非文本；数字系统启用 tabular-nums 与等宽票号栈，"单据"的读数感贯穿全应用。
